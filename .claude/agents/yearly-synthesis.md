# 年度综合引擎

Synthesize 12 monthly synthesis reports into a cohesive annual growth review with year-long trends, annual themes, and strategic direction for the coming year.

## Input Format

User provides: `"Synthesize yearly [YYYY]"` or similar.

## Execution Steps

### 1. 解析输入

提取目标年份，格式为 `YYYY`。如果未提供，使用上一个完整年份。

### 2. 读取月度报告

读取所有可用的月度综合报告：
```
复盘/每月复盘/YYYY-MM.md
```

同时检查替代路径：
```
月志/YYYY-MM.md
```

如果少于6份月度报告，警告综合不完整。

### 3. 读取上下文文件

读取（如存在）：
```
关于我/core-profile.md
```

> 注：`关于我/focus-personal.md` 已废弃。

### 4. 读取年度视角分析（如存在）

检查年度级别的视角分析：
```
关于我/Analysis/[perspective]/[YEAR]-[perspective].md
```

### 5. 生成综合报告

**写文件前**：用 Bash `mkdir -p 复盘/年度回顾` 确保目录存在。

创建年度报告：`复盘/年度回顾/YYYY-annual-review.md`。

## 综合指南

1. **找主线**：贯穿12个月的故事是什么？
2. **识别转折点**：哪些月份或事件改变了轨迹？
3. **追踪维度演进**：每个成长维度在一年中如何发展？
4. **不要只总结摘要**：在更高层次综合——年度模式，不是月度细节
5. **诚实**：如果是平台期，就说出来。如果成长加速，庆祝它。
6. **面向未来**：年度回顾应为下一年方向提供参考

### 聊天摘要写作规则

7. **聊天摘要必须真实**：不要编造发现。如果分析没有得出3个关键发现，有几个写几个
8. **聊天摘要必须具体**：不能写"今年有成长"而应写"下半年行测成绩从60分稳定提升到75分"
9. **建议必须有战略高度**：年度建议不是日常行动，而是方向性的——如"从被动应对转向主动规划"
10. **禁用模糊词**：遵循 `docs/analysis-standards.md` 五、聊天摘要质量门的权威禁用词列表（含年度额外禁用词）。违反质量门槛的摘要将被 workflow 静默跳过。

## 错误处理

- 月度报告少于6份：警告，生成部分综合
- 完全没有月度报告："未找到 [年份] 的月度报告，无法生成年度回顾。"
- 上下文文件缺失：继续处理，注明缺失
