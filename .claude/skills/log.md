# 日志即分析

用户粘贴了日志内容。你需要做两件事：**存档** + **即时分析**。

## 0. 判断单日还是多日

扫描全文，统计日期头数量。日期头匹配规则（按优先级）：

| 格式 | 正则模式 | 示例 |
|------|---------|------|
| Markdown 标题 + 中文日期 | `^#{1,2}\s+\d+月\d+日` | `## 7月3日`、`# 6月15日` |
| Markdown 标题 + 数字日期 | `^#{1,2}\s+\d+\.\d+` | `## 7.3`、`# 6.15` |
| 纯中文日期行 | `^\d+月\d+日` | `7月3日` |
| 幸福日志前缀 | `^幸福日志\s+\d+\.\d+` | `幸福日志 7.3` |

**判定**：
- 匹配到 **0或1个** 日期头 → **单日模式**（跳转到第1节）
- 匹配到 **2个及以上** 日期头 → **多日模式**（跳转到第2节）

---

## 1. 单日模式（≤1天日志）

### 1.1 存档

把用户粘贴的日志内容追加到正确的月日志文件。

**确定文件名**：
- 从内容中解析日期（如"幸福日志 7.4"或"## 7月3日" → 提取月份）
- 如果解析失败，用今天的日期
- 文件名格式：按 `.claude/shared/paths.md` 的 `input.monthly_journal_glob_cn` / `input.monthly_journal_glob_iso` 查找已有文件；找到则追加到已有文件，未找到则在 `input.journal_dir` 下新建当月日志

**追加**：
- **追加前检查**：确保 `input.journal_dir` 存在（首次使用时自动创建）
- 如果文件存在 → 在末尾加两个换行，然后追加日志内容
- 如果文件不存在 → 新建文件，写入日志内容

### 1.2 即时分析 + 输出 + 存档反馈

单日日志反馈必须和 `/daily-review` 走同一套输出格式：

1. 完成存档后，用 Task 启动 `daily-analyzer`：
   ```text
   Analyze YYYY-MM-DD
   ```
2. 不要在 `log` skill 内手写另一套分析流程；如 Task 不可用，再按 `.claude/shared/prompt-rules.md` 的「日反馈输出契约」和 `.claude/agents/daily-analyzer.md` 的输出格式临时回退。

分析完成后：
1. 将输出展示给用户
2. 确保 `output.daily_feedback` 的父目录存在 → Write 保存到 `output.daily_feedback`（覆盖已有，不添加额外说明或自检行）
3. 读取 `context.verified_patterns`，按 `.claude/shared/prompt-rules.md` 的「验证沉淀契约」写回上一条行动的验证结果：
   - `✅ 做到了`：第一次成立进入“待验证的假说”，累计 2 次成立移入“已确认的模式”
   - `❌ 没做`：记录为“行动未执行”；同类行动连续 3 次没做时，后续反馈降低行动门槛
   - `⚠️ 证据不足`：保留待验证，不升级
   - 明确反例推翻预测时，写入“已证伪的假说”

---

## 2. 多日模式（≥2天日志）— 批量导入

执行 `.claude/commands/import.md` 的步骤 2-5（按日期头拆分 → 去重 → 批量追加 → 回报），不重复描述详细逻辑。

**导完后提示**（按优先级，只显示一条）：
- 本月日志 ≥ 20天 + 月复盘不存在 → `📅 本月已积累{N}天日志。输入 /monthly-review 做月度深度复盘（约5-8分钟）`
- 本周日志 ≥ 5天 + 周复盘不存在 → `📊 本周已写{N}天日志。输入 /weekly-review 花3分钟看本周发现和调整`
- 连续3天有日志但0天有日分析 → `💡 最近积压{N}天日志未分析。输入 /review 一次性补上`
- 其他 → `💡 明天继续写日志。每天粘贴 → 即时反馈，小闭环跑起来`

---

## 3. 边界情况

- **无日期头**：尝试从内容第一行推断；失败则用今天日期，按单日处理
- **跨月粘贴**：自动拆分到不同月文件，每个文件独立去重
- **超大内容**（>2000行）：先扫描日期头 → 分批处理，每批500行
- **日期头格式不标准**：能匹配的就匹配，匹配不到的部分合并到最近一个已识别日期的条目中
- **同一天出现多次**：合并为一条（追加在一起）
