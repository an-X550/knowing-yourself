# 周志、月志、Life Design 快路径验收说明

## 目的

这份说明用于验收周志复盘、月志复盘和 `life-design` 是否真的执行了优化后的快路径。

它解决的是“怎么检查有没有按方案跑”，不直接替代命令自身的执行规则。

## 通用通过标准

三类任务都先看这三条：

1. 先消费沉淀物和证据包，再决定是否抽查原始日志。
2. 默认不读取 `PROJECT_STATUS.md`、`CHANGELOG.md`、`VERSION`、`README.md`、`AGENTS.md`、`CLAUDE.md` 或 git 状态。
3. 只有出现引用缺失、证据冲突或关键判断需要补证时，才扩大到原始日志。

只要无条件通读原始日志，或无必要读取治理文件，就判定为不通过。

## 周志复盘验收

### 允许的主输入

- 每日反馈
- `context.verified_patterns`
- `context.current`
- 三个周报视角分析
- 必要时的上周周报 / 当月月报锚点

### 通过条件

1. 报告主体建立在每日反馈和视角分析上。
2. 原始日志只在视角引用缺失、证据冲突或方向锚点不足时抽查。
3. 输出仍然遵守复盘六问结构。

## 月志复盘验收

### 允许的主输入

- workflow 传入的视角分析
- `context.current`
- `context.verified_patterns`
- 上月月报
- 核心画像

### 通过条件

1. 视角分析是主输入，而不是整月日志原文。
2. 只有视角证据冲突、上月假说需要补证或关键引用缺失时才回查日志。
3. 输出仍然遵守复盘六问和月报结构。

## Life Design 验收

### quick / standard

通过条件：

1. 先消费日反馈、周/月复盘、`current`、画像和 `verified_patterns`。
2. 原始日志只做抽样锚定，不直接作为默认主输入。
3. 输出仍包含未来实验和后续验证方式。

### full / odyssey

通过条件：

1. 允许更深的原始日志阅读。
2. 即使深读，也不应无必要读取治理文件。
3. 输出仍然是证据优先的人生校准，而不是泛泛总结。

## 验收问题单

每次验收只回答五个问题：

1. 这次主输入是不是沉淀物 / 证据包，而不是原始日志？
2. 有没有无必要读取治理文件？
3. 扩读原始日志时，是否给出了明确触发理由？
4. 最终输出结构是否仍符合原命令契约？
5. `life-design` 是否按所选模式执行了对应深度？

五项全部通过，才算真正走了优化方案。
