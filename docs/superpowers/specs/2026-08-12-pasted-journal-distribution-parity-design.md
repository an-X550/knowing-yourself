# 粘贴日志结果分发一致性设计

## 结论

只修复一个入口差异：单日日志通过 `log` skill 完成正式反馈写入、磁盘复读和 `verified-patterns.md` 验证沉淀后，复用 `/daily-review` 的现有结果分发契约。这样用户直接粘贴日志和手动运行 `/daily-review` 得到相同的飞书与滴答后置行为。

## 第一性原理依据

用户需要的是同一种日志输入产生同一种闭环结果，不能因为入口不同而静默漏掉外部分发。分析质量、验证沉淀、飞书目录和滴答行动规则已经存在；当前问题只是粘贴入口没有调用现有分发契约。

最小路径是补齐调用，不抽取新框架、不开发独立分发器，也不改变任何分析或任务生成规则。

## 执行顺序

单日日志粘贴入口按以下顺序执行：

1. 存档原始日志并调用 `daily-analyzer`。
2. 将正式反馈写入 `output.daily_feedback`。
3. 从解析出的实际路径重新读取，确认本轮新写入文件存在、非空并符合日反馈最低结构。
4. 按现有证据契约更新 `context.verified_patterns`。
5. 若请求不含“仅本地”，调用 `distribute output.daily_feedback <resolved-local-path>`。
6. 展示反馈、验证沉淀说明、实际分发摘要和可选闭环提醒。

外部分发失败不得修改、回滚或降级已经成功的本地反馈和验证沉淀。

## 停止条件

以下情况不进入结果分发：

- 日期仍未确认。
- D 级输入。
- 分析失败。
- 正式反馈未写入、复读为空或结构不合格。
- 本轮只是读取已有反馈，没有发生新写入。
- 用户本次明确要求“仅本地”。

## 修改范围

- 修改 `.claude/skills/log.md`。
- 同步 `packaging/zhiji-user-overlay/.claude/skills/log.md`，保持运行真相与用户版来源一致。
- 在 `tests/result-distribution-routing.tests.ps1` 增加粘贴入口的分发顺序、停止条件和仅本地断言。
- 按项目治理同步用户可见版本、`PROJECT_STATUS.md` 和 `CHANGELOG.md`。

## 验收

1. 新增断言在修改 `log.md` 前因缺少结果分发链路而失败。
2. 最小实现后该测试通过。
3. 项目全部现有测试通过。
4. 主项目与 overlay 的 `log.md` 保持逐字一致。
5. 不调用真实飞书或滴答；本次只验证路由契约，不制造外部副作用。

## 不做什么

- 不新增独立 `distribute` 程序、后台服务、重试队列或定时任务。
- 不修改 `daily-analyzer`、日反馈内容、验证阈值或周/月复盘。
- 不新增提醒类型，不修改飞书目录和滴答清单配置。
- 不处理与本缺口无关的历史文档和工作区文件。
