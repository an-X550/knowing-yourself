# life-design 专项命令设计

## 背景

项目当前已经形成日反馈、周复盘、月复盘、项目复盘与年度回顾链路。它们擅长从日志和复盘中识别模式、校准目标、追踪行动闭环，但仍缺少一个专门处理“长期方向不确定”的入口。

用户提供的原始 `人生设计skill.md` 基于《人生设计课》方法论，包含重力问题、工作观 / 人生观、心流与能量、奥德赛计划等有价值模块。该材料适合本项目，但原始形态更像一次长对话 prompt，不适合直接作为运行文件接入：它默认从零访谈、输出 8000-12000 字长报告、缺少项目路径契约、证据规则和后续验证闭环。

本设计将其改造为 `/life-design` 专项命令与 `life-design-synthesis` agent：先读取长期日志、日反馈、周/月/年复盘和个人画像，再只追问缺口问题，最后输出可验证的人生原型实验。

## 第一性原理判断

本项目的最小价值不是“生成完整报告”，而是：

> 至少发现一条用户自己不容易发现的洞察，并导向一个可验证的行为改变。

因此，人生设计能力只有在满足以下条件时才值得融入：

1. 它能基于长期证据发现方向性冲突，而不是复述用户当下感受。
2. 它能区分重力问题、可设计问题和伪问题，减少错误问题上的消耗。
3. 它能把长期方向拆成低成本原型，而不是给出终身规划。
4. 它能把原型实验接回日志、日反馈和月报验证链路。

如果输出只是宏大叙事或漂亮咨询报告，即使文字质量高，也不符合项目目标。

## 目标

新增一套低频专项人生设计链路：

1. 新增 `/life-design` 命令，支持主动调用。
2. 新增 `life-design-synthesis` agent，负责证据读取、问题重构、奥德赛计划和原型实验设计。
3. 在 `.claude/shared/paths.md` 增加人生设计报告输出路径。
4. 在 `/review` 智能入口中识别人生设计相关意图并路由。
5. 在月度 / 年度综合报告中加入“方向冲突升级提醒”，只提醒，不自动运行。
6. 将原始 `人生设计skill.md` 从根目录运行边界外移除或归档为设计来源材料。

## 非目标

1. 不把人生设计做成第 10 个常规月度视角。
2. 不自动在每次月报或年报后生成生活设计报告。
3. 不保留 8000-12000 字输出要求。
4. 不替用户做终身决策，不做职业测评。
5. 不在第一版引入复杂 UI、评分仪表盘或自动定时提醒。

## 方案选择

采用“手动入口 + 复盘提醒”的专项命令方案。

### 为什么不是只做参考文档

只放到方法论文档中，AI 不会稳定调用，也无法形成路径、输出和验证闭环。

### 为什么不是并入 yearly-review

年度回顾适合年度主线综合，但人生设计也会在职业迷茫、生活结构失衡或重大选择前临时发生。并入年度回顾会让触发过重，无法服务随时主动调用。

### 为什么不是新增常规视角

人生设计不是每月都该跑的分析视角。它需要更高信息密度和更强用户意愿，适合低频专项使用。放入常规视角会增加噪音和使用摩擦。

## 使用场景

### 1. 重大迷茫时主动调用

用户在职业、身份、关系、生活结构或长期目标上卡住时，可以直接运行：

```text
/life-design
/life-design 职业方向
/life-design --quick
/life-design --full
/life-design --odyssey
```

### 2. 月报 / 年报后的升级提醒

月报或年报发现以下信号时，不自动运行人生设计，只在聊天摘要或后续规划中提醒：

```text
本次复盘出现长期方向冲突、重复卡点或人生议题，可输入 /life-design 做一次人生设计校准。
```

触发信号：

1. 连续多月出现同一类方向性困惑。
2. 工作观和人生观明显冲突。
3. 日志中反复出现“要不要继续”“这条路是不是错了”“不知道想要什么”等表达。
4. 月报或年报发现下阶段规划只能做局部修补，无法回答长期方向。
5. 某个目标反复失败，根因不像执行问题，而像目标本身与用户真实动机冲突。

## 命令设计

新增文件：

```text
.claude/commands/life-design.md
```

命令语义：

| 输入 | 行为 |
|------|------|
| `/life-design` | 默认读取最近 90 天材料，生成标准人生设计校准 |
| `/life-design 主题` | 围绕指定主题生成校准，如职业方向、生活节奏、关系选择 |
| `/life-design --quick` | 只做问题重构 + 1 个 7 天原型实验 |
| `/life-design --full` | 读取更长周期材料，输出更完整报告 |
| `/life-design --odyssey` | 聚焦三个奥德赛人生原型 |

默认模式为标准模式。若参数冲突，以更具体的模式为准。

## Agent 设计

新增文件：

```text
.claude/agents/life-design-synthesis.md
```

职责：

1. 读取路径契约和分析规则。
2. 收集个人画像、当前状态、日志、日反馈、周报、月报和年报。
3. 基于证据先形成内部人生设计假说。
4. 仅在关键证据缺失时提出最多 3 个缺口问题。
5. 输出人生设计报告，并写入指定路径。
6. 为未来 7 天设计低成本原型实验。
7. 明确后续日志、日反馈、月报如何验证。

禁止：

1. 不得把人生设计报告写成心理诊断。
2. 不得把重力问题包装成“只要努力就能解决”。
3. 不得输出超过模式限制的长文。
4. 不得替用户选择唯一人生方案。
5. 不得给出无法在 7 天内观察信号的行动建议。

## 数据读取策略

`life-design-synthesis` 必读：

1. `.claude/shared/paths.md`
2. `.claude/shared/prompt-rules.md`
3. `docs/analysis-standards.md`
4. `关于我/core-profile.md`，若不存在则标注画像缺失
5. `关于我/current.md`，若不存在则标注当前状态缺失

按模式读取材料：

| 模式 | 默认读取范围 |
|------|-------------|
| `quick` | 最近 30 天日志、最近 7 条日反馈、最近 1 份月报 |
| 标准 | 最近 90 天日志、最近 14 条日反馈、最近 1-3 份周/月复盘 |
| `full` | 最近 180 天日志、最近 30 条日反馈、最近 3-6 份月报、年度报告 |
| `odyssey` | 标准范围，额外聚焦长期选择、工作观、人生观、能量证据 |

如果材料不足，报告中写明边界，不补造结论。

## 输出路径

在 `.claude/shared/paths.md` 新增：

```text
output.life_design_report | 复盘/人生设计/YYYY-MM-DD-life-design.md
```

调用方负责确保父目录存在。若同一天多次生成，可追加主题后缀：

```text
复盘/人生设计/YYYY-MM-DD-life-design-{topic}.md
```

## 报告结构

标准报告控制在 2000-3500 字，`quick` 控制在 1000-1800 字，`full` 最多 5000 字。

```markdown
---
created: YYYY-MM-DD
mode: standard|quick|full|odyssey
topic: 主题或 general
evidence_range: YYYY-MM-DD..YYYY-MM-DD
---

# 人生设计校准：YYYY-MM-DD

## 聊天摘要
[3 个关键判断 + 1 个本周原型行动]

## 一、你现在在哪里
[健康 / 工作 / 娱乐 / 爱四个仪表盘。必须引用日志、反馈或复盘证据。]

## 二、真正的问题是什么
[区分重力问题、可设计问题、伪问题或错误前提。]

## 三、你的指南针
[工作观、人生观，以及二者一致或冲突处。]

## 四、能量地图
[充电、消耗、擅长但透支、想试但未验证。]

## 五、三个奥德赛原型
[现有路径优化版、替代路径版、无惧评价版。每个都是 A 计划。]

## 六、未来 7 天原型实验
[最多 3 个低成本实验。每个包含行动、观察信号、验证方式。]

## 七、下次如何验证
[下一篇日志、日反馈、下次月报应观察哪些信号。]
```

## 证据规则

1. 每个关键判断至少给出一条证据：日志日期、日反馈、周报、月报、年报或画像。
2. 没有证据时写“证据不足”，不写成结论。
3. 允许提出假说，但必须标注为“待验证假说”。
4. 原型实验必须能在 7 天内观察信号。
5. 报告必须包含反例、限制或边界，避免过度确定。

## 与现有链路的关系

人生设计链路位于现有复盘系统之上：

```text
日志 / 日反馈 / 周报 / 月报 / 年报
        ↓
识别方向性冲突或主动迷茫
        ↓
/life-design
        ↓
7 天原型实验
        ↓
日反馈和下次月报验证
```

`daily-analyzer` 不直接调用人生设计，只负责在原型实验期间追踪用户是否执行和观察到什么。

`monthly-synthesis` 和 `yearly-synthesis` 只负责识别升级提醒，不自动生成报告。

`review` 统一入口可以把“人生设计”“职业方向”“奥德赛计划”“长期方向”等关键词路由到 `/life-design`。

## 验收标准

1. `/life-design` 命令存在，并能说明参数和模式。
2. `life-design-synthesis` agent 明确读取证据、输出路径、字数边界和禁止事项。
3. `paths.md` 包含 `output.life_design_report`。
4. `/review` 能识别人生设计相关意图。
5. 月报 / 年报 agent 能在方向冲突明显时输出升级提醒，但不会自动运行人生设计。
6. 报告结构包含“7 天原型实验”和“下次如何验证”。
7. 所有新增运行文件使用 YAML frontmatter。
8. README、PROJECT_STATUS、CHANGELOG、VERSION 与新增命令 / agent 同步。

## 风险与控制

| 风险 | 控制方式 |
|------|----------|
| 变成长篇咨询报告 | 限制字数，强制 7 天原型实验 |
| 与月报 / 年报重复 | 定位为低频方向校准，不作为常规视角 |
| 证据不足仍强行判断 | 明确证据边界和“待验证假说” |
| 用户忘记使用 | 月报 / 年报只在方向冲突时提醒 |
| 过度自动化 | 第一版不自动触发，只手动运行 |
| 根目录污染 | 实施时处理原始 `人生设计skill.md` |

## 自检结论

1. 设计采用用户确认的方案 B：新增 `/life-design` 专项命令 + agent。
2. 使用场景覆盖主动迷茫调用和月报 / 年报后的升级提醒。
3. 保留原始 skill 中最有价值的重力问题、指南针、能量地图和奥德赛计划。
4. 移除原始 skill 中不适合项目的长报告、从零访谈和无证据输出。
5. 输出接回项目最小价值：产生洞察，并导向可验证行为改变。
