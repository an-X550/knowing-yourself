# README 第一性原理重构设计

## 目标

重写主项目与用户分发版的 README，使读者先理解“知己为什么存在、如何产生价值”，再按自身身份进入项目维护或实际使用。

知己的核心价值不是生成更多报告，而是：

```text
发现模式 → 形成行动 → 后续验证 → 沉淀认识
```

文档的最小成功标准是：新读者能准确理解知己与普通 AI 总结工具的区别，知道第一次如何开始，并理解 AI 的结论只是待验证假说，最终判断权属于用户。

## 受众边界

### 主项目 README

面向项目维护者、潜在贡献者，以及希望了解完整产品的人。它既是产品全景介绍，也是进入架构、状态、规范和开发文档的导航入口。

### 用户版 README

只面向最终用户。它是一份可直接照做的产品说明和使用手册，不出现冒烟测试、分发验收、导出流程、上级仓库维护方式等开发者内部内容。

## 共同叙事主线

两份 README 共享以下稳定认知，但根据受众调整深度和措辞：

1. 人很难在当下识别跨时间模式，也容易遗忘过去的洞察。
2. AI 擅长整理证据和生成假说，但不能替人定义人生或宣布心理真相。
3. 有价值的反馈必须落到一个足够小、可以观察结果的行动。
4. 后续日志负责验证行动结果，并逐步形成已验证、已证伪或待验证的长期认识。
5. 一次干预失败只说明这次方法没有奏效，不能直接证伪背后的行为假说。

## 主项目 README 信息架构

1. 一句话定位与最小成功定义。
2. 第一性原理：用户盲区、原子价值公式和核心闭环。
3. “行为假说 vs 干预实验”及验证沉淀机制。
4. 人机显式契约：AI、人和系统各自负责什么，不负责什么。
5. 完整功能地图：日志录入与单日反馈、日志教练、统一复盘入口、周/月/项目/年度复盘、人生设计。
6. 快速开始和入口选择，兼顾自然语言与命令。
7. 系统架构与数据流，解释命令、代理、视角和共享契约。
8. 主项目、用户分发版和变体源之间的边界。
9. 开发原则和新增功能必要性闸门。
10. 模型建议、项目结构与文档导航。

主 README 不展开内部测试步骤，只链接当前状态、开发规范和必要的维护文档。

## 用户版 README 信息架构

1. 产品定位：它解决什么问题、不是什么。
2. 安装准备与第一次使用的最短路径。
3. 如何写或粘贴日志，模板不是质量门槛。
4. 完整功能及各自适用时机。
5. 从日志到验证沉淀的闭环操作说明。
6. 用通俗示例解释行为假说、干预实验和验证结论。
7. 人机角色契约与用户最终判断权。
8. 自然语言说法与命令对照。
9. 输出位置、隐私保护、证据不足时的降级行为。
10. 常见问题和下一步建议。

用户版删除以下内容：

- 冒烟测试和测试清单；
- 内测反馈采集说明；
- 维护者与使用者的仓库分工；
- 上级项目、覆盖层、导出脚本和同步流程；
- 其他只服务开发治理的目录说明。

## 人机角色契约

### AI 负责

- 从日志和历史材料中提取事实与跨时间模式；
- 明确区分事实、推断、建议和证据不足；
- 把模式写成可以被验证或证伪的行为假说；
- 提出低成本、可执行、可观察结果的干预实验；
- 在后续反馈和周期复盘中追踪验证状态；
- 在证据不足时降低结论强度，而不是补完故事。

### 用户负责

- 提供尽量真实的记录，不为迎合 AI 篡改体验；
- 决定是否采纳、修改或拒绝建议；
- 执行实验或如实记录没有执行；
- 在后续日志中记录结果、反例和感受；
- 保留对自身经历、价值和人生方向的最终解释权。

### AI 不负责

- 诊断心理或医疗问题；
- 把单篇日志中的推断包装成确定事实；
- 替用户做价值选择或重大人生决定；
- 用更多报告掩盖没有行动、没有验证的问题。

## 行为假说与干预实验示例

```text
观察：近三次拖延都发生在任务边界模糊时。
行为假说：任务边界不清会显著提高启动阻力。
干预实验：明天只写出第一步，并执行 10 分钟。
实验结果：仍未启动。
正确结论：这次干预没有奏效，继续检查精力、环境或任务价值。
错误结论：行为假说已经被彻底证伪。
```

文档应强调：假说需要跨时间证据，实验是一次具体尝试，两者不可混为一谈。

## 写作与实现约束

- 简体中文，优先使用普通用户能理解的表达。
- 先讲价值和场景，再讲命令、目录和实现。
- 功能必须全面，但避免重复描述同一能力。
- 不承诺 AI 能“看穿”用户，不使用确定性心理归因。
- 保留现有有效链接，并在修改后检查 Markdown 相对链接。
- 用户版 README 的真实维护源是 `packaging/zhiji-user-overlay/README.md`；修改后通过导出流程同步到 `zhiji-user/README.md`，避免双向手改。

## 验收标准

1. 主 README 清楚说明产品价值、完整能力、闭环机制、人机边界和项目结构。
2. 用户版 README 不依赖开发背景即可完成第一次使用。
3. 两份 README 都准确解释行为假说、干预实验和验证沉淀。
4. 用户版不包含冒烟测试、导出、维护者或内部验收内容。
5. 功能名称、命令、路径与当前运行真相一致。
6. 所有 Markdown 相对链接有效。
7. 主项目版本、项目状态和 CHANGELOG 按公开文档变更规则同步。
