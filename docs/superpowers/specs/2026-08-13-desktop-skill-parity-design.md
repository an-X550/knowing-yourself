# 知己桌面端核心能力对齐设计

## 结论

桌面端不应逐条复制 Skill 的命令，而应补齐 Skill 已验证的用户闭环：

`记录事实 → 获得有证据的日反馈 → 验证上一行动 → 周/月/年归纳 → 方向校准`

本轮选择“按用户目标对齐”的方案：保留现有五个一级入口，把新增能力收纳进“复盘”的渐进展开区域。飞书、滴答清单以及只服务开发者的命令不进入桌面端。

## 第一性原理审计

用户购买的不是命令数量，而是三种结果：能够持续记录、能够从自己的材料得到可信反馈、能够把反馈转化为下一次可验证行动。任何功能只有同时满足“有当前问题证据、直接服务核心结果、没有更简单替代、上线后可验证”才值得实现。

| 能力 | Skill | 当前桌面端 | 判断 |
|---|---|---|---|
| 日志与项目关联 | 完整 | 完整，支持补写日期与 CRUD | 保持 |
| 每日反馈 | 有证据、上一行动闭环、五分钟行动、可观察预测 | 已生成，但上一行动结果未渲染，约束偏弱 | 立即修复 |
| 周/月/项目复盘 | 完整 | 已有预览、生成、历史和删除 | 保持 |
| 年度复盘 | 已有 | 缺失 | 作为低权重深度工具加入，并设置材料门槛 |
| 日志质量教练 | 已有 A-D 就绪度与改进建议 | 缺失 | 高复用、低复杂度，加入 |
| 人生设计 | 已有多档模式 | 缺失 | 只加入高性价比“快速方向校准”，不复制重型模式 |
| 个人资料参与分析 | Skill 会使用长期上下文 | 桌面端开关只保存、不生效 | 修复语义缺口；仅开启时注入 |
| 假说/模式台账 | 有跨期验证文件 | 周/月已间接消费下级复盘，无稳定桌面样本证明独立台账必要 | 暂不新增数据模型，避免伪精确和维护负担 |
| 主题思考、收藏、current.md | 面向对话式 Agent | 无 | 暂缓；直接搬到 GUI 会增加入口与概念负担 |
| 旧格式导入 | 有命令 | 已有完整备份导入导出 | 暂缓专用迁移器；现有备份已覆盖普通用户数据可携带性 |
| 飞书、滴答清单 | 有集成 | 无 | 按用户要求排除 |

## 本轮范围

### 1. 可信每日反馈

- 每日反馈明确展示“上一行动：已完成 / 未完成 / 证据不足”及证据。
- 提示词只允许依据材料，要求一个引用证据、一个五分钟内行动和一个可观察预测。
- 保持既有 JSON 校验与 Markdown 存储，不引入数据库或迁移。

### 2. 个人资料真正参与 AI

- `enabledForAi=false` 时任何模型请求都不包含个人资料。
- `enabledForAi=true` 时每日、周期和深度分析都收到独立的 profile 字段。
- 前端文案准确说明开关效果，不展示技术实现细节。

### 3. 三个渐进式深度工具

在“复盘”页现有周/月/项目卡片下仅显示一个“更多洞察”按钮，展开后出现：

- 日志质量教练：至少 3 篇日志，输出就绪度、缺口和下一次记录建议。
- 年度回顾：至少 6 份月度复盘，避免用零散材料制造年度结论。
- 方向校准：使用最近一段时间的日志、复盘和经授权的个人资料，只输出问题重述与一个 7 天实验；不复制标准/完整/奥德赛等重型模式。

三者复用既有“预览材料 → 用户确认 → 生成 → 本地保存 → 可删除”链路，历史记录仍位于同一页面。

### 4. 首页自动建议

现有记录、日反馈、周复盘优先级不变。只有更高频任务已经完成且材料满足门槛时，才建议月复盘、年度回顾或日志质量检查；首页始终只给一个主建议，不新增面板。

## 数据与架构

- 扩展既有 `Review` 类型为 `coach | yearly | life-design`，继续存入用户本地 `reviews/` Markdown 文件。
- 新建 `GenerateInsightReview` 应用服务，复用仓储、任务取消、AI Provider、预览令牌和材料摘要，不把提示词逻辑放进 React 或 IPC。
- 新增独立 insight IPC schema，避免对现有周期复盘 schema 使用条件 refinement，保留边界校验清晰性。
- 所有 AI 上下文设置数量上限，方向校准优先使用高层复盘，防止超长请求。
- `.claude/` Skill 运行逻辑不修改；桌面端只消费相同方法论。

## 交互原则

- 不增加一级导航，不改变现有“开始—日志—复盘—项目—设置”心智模型。
- 高频任务默认可见，低频工具按需展开；同一时间只展示一个配置表单。
- 继续使用现有卡片、间距、按钮层级和系统控件，不引入新的 UI 依赖。
- 错误写成用户可行动的原因，例如“至少需要 3 篇日志”，不暴露堆栈。

## 验收

1. 开启/关闭个人资料参与 AI 后，测试能证明请求内容相应包含/不包含资料。
2. 每日反馈正文包含上一行动状态；无上一行动时不显示空章节。
3. 三个深度工具都必须先预览；材料不足时阻止生成并解释门槛。
4. 新结果能在历史复盘查看并安全移入回收站，备份校验能够识别。
5. 默认复盘页仍只突出周/月/项目；“更多洞察”未展开时无额外配置。
6. 单元、集成、类型、lint、端到端与 Windows 打包验证通过。
