# 知己 Windows 客户端数据生命周期设计

## 真实问题

用户需要纠正误建、误写和过期状态，并确认本地资料仍由自己控制。目标不是让每种实体形式上拥有完整 CRUD，而是在不破坏日志、项目与复盘来源关系的前提下，补齐必要的纠错和退出路径。

## 已知事实与约束

- 日志、复盘为本地 Markdown，项目为本地 JSON；复盘通过 `sourceIds` 引用日志或下级复盘，日志通过 `projectIds` 引用项目。
- 当前日志可新建、查看、编辑但不可删除；项目可新建、查看、归档但不可重命名、恢复或删除；复盘可生成、查看但不可删除；API Key 可保存但不可清除。
- 删除源材料后，已生成复盘仍可作为历史快照阅读，但不能再假装所有来源仍存在。
- Windows 客户端可以使用 Electron `shell.trashItem` 将文件移入系统回收站，避免不可恢复的直接删除。
- 不引入新 UI 框架，不级联删除，不自动改写既有日志或复盘正文。

## 必要性结论

本需求值得实现：问题来自当前真实使用；直接服务本地优先和普通用户可用性；归档不能解决误建、名称冲突和隐私退出；完成后可通过仓储、IPC、页面和真实 Electron 测试立即验证。

## 设计

### 日志

- 历史日志详情提供“移到回收站”。
- 删除前显示日志日期，并明确“已有复盘不会同步删除”。
- Main Process 按稳定 ID 查找真实文件，再调用 `shell.trashItem`；Renderer 永远不能传文件路径。
- 删除后刷新列表。已有复盘保留为生成时的历史快照，其 `sourceIds` 允许指向已移除来源。

### 复盘

- 历史复盘详情提供“移到回收站”。
- 删除前明确只移除当前复盘文件，不删除来源日志，也不级联删除引用它的月报等结果。
- 删除后刷新历史列表。

### 项目

- 项目名以 `trim().toLocaleLowerCase()` 作为比较键，在所有进行中和已归档项目中全局唯一；校验必须位于 Main Process 仓储边界，前端提示不能替代后端约束。
- 进行中项目支持重命名和归档；已归档项目支持恢复和重命名。
- 仅无关联日志的项目可以移到回收站。有关联日志时 Main Process 拒绝操作并返回明确错误，不自动解除关联、不删除日志。
- 恢复项目保留原 ID，使历史日志关联自动恢复可见。

### AI Key

- 设置页提供“移除已保存 Key”，仅删除当前所选服务商的加密凭证，不删除公开的服务商、地址或模型配置。
- 操作二次确认；完成后刷新全局 AI 状态，首页立即显示未配置。

### 下拉控件

- 使用全局 CSS 统一原生 `select` 的高度、内边距、圆角、边框、背景、箭头和 `focus-visible` 状态。
- 保留原生语义、键盘操作和 Windows 选项弹层，不开发自定义组合框，不新增依赖。

## 错误与安全边界

- 删除目标不存在返回 `NOT_FOUND`；项目重名与有关联日志的删除返回可读的 `INVALID_INPUT`。
- 回收站调用失败时不刷新、不伪装成功，用户原文件保持由操作系统结果决定。
- 所有 ID 经现有 Zod 稳定 ID Schema 校验；文件路径继续通过 `resolveInsideRoot` 限制在数据目录内。
- 不提供批量删除、清空全部、级联删除、回收站管理或撤销协议；恢复文件由 Windows 回收站负责。

## 验收标准

1. 日志和复盘能从详情页经确认移入 Windows 回收站，其他资料不被删除。
2. 项目名不能与任意状态的既有项目重复；项目可重命名、归档、恢复。
3. 无日志项目可移入回收站；有关联日志项目被明确阻止。
4. 当前服务商 API Key 可清除，所有依赖 `hasApiKey` 的界面状态同步刷新。
5. 所有原生下拉视觉一致，键盘与无障碍语义保持。
6. 单元、集成、类型、Lint、Electron E2E 和 Windows x64 打包验证通过。
