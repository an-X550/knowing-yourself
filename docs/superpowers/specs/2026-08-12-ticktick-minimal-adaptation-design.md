# 知己 × 滴答清单：四来源最小适配设计

## 结论

滴答清单只承担“执行入口和到期提醒”，知己继续承担“从日志发现模式、形成行动、根据后续日志验证”。本次不建设任务同步系统，只收敛已有单向创建能力：让每日反馈、周复盘、月复盘和已确认主题思考中的合格行动，以最少字段、适当确认和精确防重进入固定清单“知己行动”。

本设计覆盖 `2026-08-11-result-distribution-design.md` 中的 TickTick 部分；原设计的本地权威、飞书分发、渠道独立失败和凭证边界继续有效。

## 一、第一性原理审查

### 真实问题

知己已经能形成明日行动和下一周期规划。当前摩擦发生在分析完成之后：用户需要把真正准备执行的行动再次改写并录入滴答清单。要消除的是这次机械搬运，而不是让知己接管滴答清单。

### 已知事实

- 日反馈到滴答已经有真实创建记录，现有官方 MCP、目标清单、配置和本地状态骨架可复用。
- 周复盘、月复盘已经有稳定的下一周期规划章节；行动是否值得进入任务清单，需要在报告生成后才能判断。
- 已确认主题思考可能含当前行动卡，也可能只有等待条件或“当前不行动”。
- 用户希望滴答任务只显示任务标题和截止时间。
- 知己判断行动是否完成的证据来自后续日志，不来自滴答任务状态。

### 未验证假设

- 四来源适配能实质减少手工复制，而不会制造任务噪声。
- 周/月最多三项、每日最多一项足以覆盖真实执行需要。
- 精确判重足以应对当前低频单用户场景。

这些假设只通过真实使用验证，不通过增加读取、模糊匹配或后台状态来“预防性解决”。

### 硬约束

- 本地报告是权威结果；滴答创建只是后置副作用。
- TickTick 适配器只允许 create-task，不读取、搜索、更新、完成或删除任务。
- 外部失败不回滚本地写入，不改变报告正文，也不参与完成判断。
- 用户在当前生成请求中说“仅本地”时，本轮同时跳过飞书和滴答，不留下永久标记。
- 不把原始日志、画像、中间分析、报告摘要或文件路径写入滴答任务。

### 最小杠杆

复用现有结果分发契约、四个既有内容入口、官方 MCP、运行配置和本地 JSON 状态；只调整来源白名单、候选提取、确认门、字段、日期、判重和失败语义。不要新建 command、agent、workflow、数据库、队列或常驻进程。

## 二、范围

### 纳入

| 来源 | 进入滴答的内容 | 创建时机 | 数量上限 |
|---|---|---|---:|
| 每日反馈 | `⚡ 明天试试` 中唯一合格行动 | 新反馈写入并校验后自动创建 | 1 |
| 周复盘 | `## 六、下周规划` 中用户最终选定的行动 | 展示最终候选并获得整组确认后 | 周/月当日合计 3 |
| 月复盘 | `## 六、下月规划` 中用户最终选定的阶段行动 | 展示最终候选并获得整组确认后 | 周/月当日合计 3 |
| 已确认主题思考 | `0. 当前行动卡` 中唯一当前行动 | 保存主题与创建任务合并确认后 | 1 |

### 排除

- 项目复盘、年度回顾和人生设计的滴答任务提取；它们原有本地生成和飞书分发不变。
- 任意普通对话中的任务代办。用户直接要求“创建一个滴答任务”时，应直接使用滴答能力，不经过知己报告分发和状态。
- 滴答完成状态读取、回写、双向同步、任务修改或删除。
- 子任务、清单项、标签、优先级、描述、附件、来源前缀和自定义提醒。
- 后台重试、定时扫描、历史批量补建、模糊语义去重、日期容差和工作量排程。

## 三、合格行动与 SMART 标题

候选必须同时满足：

1. 用户已经明确选择或报告已经明确提出为下一步；
2. 行动处于用户可控范围；
3. 有可观察的结果或检查条件；
4. 能仅凭标题和截止时间理解要做什么；
5. 不需要模型补造目标、数量、投入或判断标准。

SMART 只用于压缩标题，不在滴答中展开五个字段。标题可以使用报告已经包含的信息进行具体化和去冗余，但不得发明数量、频率、成果或投入。宽泛方向、价值口号、纯分析、事实陈述、“也许可以”、只有长期目标而没有近期结果、依赖他人且没有用户可控动作、等待外部条件的事项均不创建。

多步骤如果共同服务一个可独立检查的结果，只建一个结果任务；只有步骤各自形成独立结果或不同截止时间时才拆分，且仍受数量上限约束。重复行动默认压缩为一个周期结果任务；只有原计划明确要求固定频率且每次提醒确有必要时，才创建重复任务。

## 四、交互与数据流

### 每日反馈

1. 首次生成或有效重跑的新反馈成功写入、复读并完成必要验证沉淀。
2. 若当前请求含“仅本地”，停止外部分发。
3. 提取唯一合格行动，形成最终标题与截止时间。
4. 精确判重后自动创建；不显示预览、不要求确认。
5. 历史补写仅在目标日期是今天或昨天时自动创建。更早日期不自动滚动截止日；若行动仍有价值，只展示候选并要求用户给出新的未来截止时间。

同一天“重新分析/刷新”若产生完全相同的标题和截止时间，报告“已存在，未重复创建”。若产生不同候选，不自动创建第二项；展示新标题与截止时间，询问是否创建替代任务，旧任务由用户在滴答中处理。

### 周复盘与月复盘

1. 报告成功写入并复读；飞书仍按已有独立渠道规则处理。
2. 若当前请求含“仅本地”，不显示滴答候选，也不创建。
3. 从下一周期规划提取 0–3 个合格候选，只显示 `标题｜YYYY-MM-DD` 或明确时间。
4. 用户可用自然语言删除、修改标题或截止时间。只使用报告已有事实；信息不足时询问，不擅自补齐。
5. 修改后重新展示一次最终整组。
6. 只有用户对最终整组明确确认后才创建。“同步到滴答”写在报告生成请求中只表示同步意图，不替代对最终候选的确认；“看起来可以”“我再想想”等含糊表达不创建。
7. 未确认的候选不排队、不催办、不写入待创建状态。它只保留在原报告中；以后只有新复盘再次提出或用户明确请求时才重现。

周/月同一自然日合计默认最多创建 3 项。已经成功创建的任务占用当日名额，新报告只展示剩余名额。用户说“全部创建”不自动突破；只有明确说“本次允许超过 3 项”才一次性覆盖默认上限，不改变以后规则。每日行动不占这个上限。

若没有合格行动，不显示空任务块，只输出：`本次没有可直接创建的滴答任务。`

### 已确认主题思考

主题首次保存或有效更新前，向用户展示沉淀摘要。若存在唯一合格的当前行动，最终确认同时涵盖“保存主题”和“创建该任务”；用户可说“只保存主题”而不创建。主题只有等待条件、没有当前可执行行动或写明“当前不行动”时，不创建任务。

主题的一次性实验没有明确日期时，默认截止日为用户确认后的第 7 个本地日历日。主题行动不纳入周/月当日三项上限。

## 五、日期规则

- 所有日期按 `Asia/Shanghai` 本地日历解释；默认创建全天任务。
- 只有原计划明确包含具体时间时才创建定时任务；不设置自定义提醒，使用滴答全局默认提醒。
- 今天或昨天的日反馈，默认截止到本次成功生成后的下一本地日历日。
- 周复盘无明确日期时，截止到对应下一 ISO 周的周日。
- 月复盘无明确日期时，截止到对应下一自然月最后一天；只接收下月可检查的阶段结果，不把长期方向直接建成任务。
- 相对日期优先锚定报告所规划的下一周期，而不是实际生成日。创建前统一显示绝对日期。
- 日期已过去时不创建、也不自动顺延。周/月/主题要求用户确认新的未来日期；过期事实留给复盘判断。

## 六、任务字段与清单

每个任务只向 MCP 传递：

| 字段 | 规则 |
|---|---|
| title | 最终 SMART 化标题，不加 `[知己]` 或来源前缀 |
| due date/time | 按日期规则得到的绝对日期或明确时间 |
| list | 首次设置从唯一现有“知己行动”取得 `project_id` 并保存；正式分发只使用该 ID |

不传 description、检查条件、来源路径、报告摘要、标签、优先级或自定义提醒。检查条件应已被压缩进可理解的任务标题；若做不到，则候选不合格或需要用户补充。

系统不自动创建、迁移或修复“知己行动”清单。首次设置或用户明确重新绑定时只查询清单一次：名称完全匹配且恰好一个时保存 `project_id`；正式分发不再查询。零个或多个匹配、清单不存在或不可访问时，本次创建失败，只给一条设置指引；用户修复后明确重试失败项。

## 七、精确判重、状态与变更

自动判重键是：

```text
normalized_title + exact_due_date_or_time
```

标题只做 Unicode、首尾和连续空白规范化；不做语义相似判断。相同标题但不同截止时间：周/月作为“可能重复”交给用户决定；每日可视为新的执行周期自动创建。不同来源出现完全相同的标题和截止时间，只创建一次。

本地最小状态按成功任务保存：

- 来源类型与本地来源标识；
- 最终规范化标题；
- 截止日期或时间；
- 本次结果与远端 `task_id`；
- `attempted_at`。

不保存 description、完成记录、修改历史或其他滴答数据。状态只用于本地防重和失败项重试，不读取远端任务来补全。

报告后来修改时，不自动更新或删除既有任务。若行动或日期实质变化，形成一个新候选，由用户确认是否创建替代任务；旧任务由用户在滴答中处理。

## 八、失败与反馈

报告成功和滴答成功相互独立。创建后只给最小反馈：

```text
已创建 2 项滴答任务：
- 完成 X｜2026-08-16
- 提交 Y｜2026-08-18
```

部分失败时逐项标明“已创建/失败”，不输出任务 ID、完整响应或技术堆栈。一组任务失败后，只允许用户明确重试失败项一次；成功项用本地状态跳过。再次失败即停止，不建立后台重试。

如果远端创建成功但本地状态写入失败，明确告知“任务已创建，但防重记录失败”；不自动再次创建，也不读取滴答重建记录。未来遇到相同候选时提示重复风险，由用户决定。

用户修改失败项的标题或截止时间后，它成为新候选，需要重新确认，不算重试。

## 九、现有结构中的最小改动

1. 收敛 `.claude/shared/contracts/result-distribution.md` 的 TickTick 章节，保留飞书和渠道独立性。
2. 在日反馈入口保留自动创建，但加入历史日期、同日重跑和最小反馈规则。
3. 在周/月入口加入“候选展示 → 修改 → 最终整组确认 → 创建”门，不让通用分发调用直接创建。
4. 在主题确认写入入口加入“保存 + 创建”合并确认和“只保存主题”分支。
5. 把运行配置中的 TickTick 开关收敛到四个来源；项目/年度/人生设计只保留飞书。
6. 调整状态和防重语义为标题加精确截止时间；保留现有状态文件的兼容读取，不迁移或回读旧任务。
7. 同步 overlay、导出用户版、设置文档、README、项目状态、版本和变更记录。
8. 扩展现有契约测试与路由测试；不创建新的测试框架或生产守护进程。

## 十、测试与验收

### 离线契约测试

- 只有四个来源可进入滴答；项目/年度/人生设计被拒绝。
- 日反馈自动创建；周/月没有最终确认绝不创建；主题支持“保存并创建”和“只保存”。
- MCP 字段只含标题、截止时间和目标清单，不含 description、路径、标签等字段。
- 默认日期、相对日期锚点、历史过期和全天/定时规则正确。
- 周/月当日合计上限、显式一次性覆盖和每日独立上限正确。
- 精确标题加截止时间判重；同标题不同日期不自动判重。
- 部分失败只重试失败项；报告修改不更新或删除旧任务。
- “仅本地”跳过候选展示和任务创建，且不持久化。
- 主运行真相、overlay 和导出用户版保持同步。

### 正式使用验收

采用两层最小证据，不再等待真实使用次数累计：

1. `offline_end_to_end_acceptance`：使用脱敏夹具模拟 3 次日反馈、1 次周复盘、1 次月复盘、1 次主题思考，以及仅本地、精确防重、旧状态、部分失败重试和只从日志判断完成。模拟必须覆盖完整来源决策和状态结果，但 `remote_write = false`，不向滴答写测试任务。
2. `official_mcp_smoke_test`：确认当前环境存在账号区域对应、已授权且唯一的官方单项创建能力，并核对它接受标题、截止日期/时间和目标清单标识。若必须证明账号侧写入，则只创建一项脱敏一次性任务，由用户在官方客户端目视确认和清理；不读取、搜索、更新或删除其他任务。

`tests_pass_formal_use`：自动化端到端模拟验收、官方 MCP 能力预检和全量回归全部通过，即认为适配可正式使用，不再要求等待 3 次真实日反馈或额外的真实周/月样本。该结论证明知己侧规则和当前连接前置条件可用，不承诺外部服务未来每次调用都在线；正式调用失败仍按既有逐项失败与显式重试规则处理。

## 十一、停止条件

实现到上述验收所需能力即停止。除非真实使用反复出现可复现问题，否则不增加：

- 双向同步或完成状态读取；
- 模糊去重、相似度模型或日期容差；
- 自动修改、删除或迁移任务；
- 后台队列、常驻服务或定时扫描；
- 更多来源、更多任务字段或复杂优先级系统。
