# 主题思考六问结构设计

## 目标

让主题思考留下可回查的个人思考痕迹、接受有证据的外部审查，并最终落到可验证行动；避免抽象标题、重复追加和“漂亮但无用”的思考输出。

## 范围

修改现有主题思考运行契约、用户版主题模板及其一致性测试。保留现有确认写入、动态主题、安全路径、按需召回和当前表达优先等边界。

不新增 command、agent、hook、报告类型、目录层级或单独的“审查文件”。

## 固定结构

每个主题文件使用以下六个面向用户的问题作为一级标题：

1. `我在困扰什么？`
2. `我目前怎么理解？`
3. `我凭什么这样想，哪里可能错？`
4. `什么值得继续保留？`
5. `接下来怎么试？`
6. `我的看法怎么变了？`

六问是检查思考闭环的问题清单，不要求六个部分篇幅相等。各部分按证据、问题复杂度和行动需要展开：高风险判断、明确行动和反例可写细；没有新证据时短写并说明原因，禁止为了填满标题平均扩写泛泛内容。

### 各部分职责

| 标题 | 必须回答 | 内容边界 |
|---|---|---|
| 我在困扰什么？ | 反复出现的现象、情境、感受或冲突是什么？ | 不抢先解释原因；合并同义提问，保留问题痕迹。 |
| 我目前怎么理解？ | 用户当前如何解释问题？ | 显式区分事实、推断与价值判断；不把 AI 判断伪装成用户观点。 |
| 我凭什么这样想，哪里可能错？ | 依据、反例、证据缺口和外部审查是什么？ | 来源链接或日期、反例、推理跳跃、替代解释、风险与未知信息；AI 可以挑战价值和目标，但须说明依据。 |
| 什么值得继续保留？ | 哪些原则、做法、资源或价值经过支持，值得继续使用？ | 写适用条件与边界；不把单次成功升级为通用规律。 |
| 接下来怎么试？ | 当前用什么最小行动验证或改善？ | 同时只允许一个进行中的行动实验；写触发条件、最小动作、预期观察和验证时间。 |
| 我的看法怎么变了？ | 哪个认识被保留、修正、增加反例或仍未解决？ | 只在当前认识实质变化时追加，不记录逐字会话。 |

## 硬约束

1. 每个重要判断标明或可识别为事实、推断或建议。
2. AI 的审查必须具体指出证据缺口、反例、推理跳跃、价值冲突、风险或替代解释之一；不得用空泛的“可能不对”代替审查。
3. 每个建议必须对应前文的一个问题或推断；方案未经验证前只能称为行动实验，不得写成答案。
4. 同一主题同时只保留一个进行中的行动实验；其他想法放入未决问题或后续候选，不抢占当前行动。
5. 更新主题时优先修订前五部分；只有认识发生实质变化才向第六部分追加演化记录。
6. 详细日志、文章和引用保留为来源入口，不把主题文件扩写成会话转录或资料仓库。

## 数据与运行流

```text
用户主动探讨
  → AI 区分事实 / 推断 / 价值判断
  → AI 进行有依据的反例与风险审查
  → 用户确认归纳
  → 写入六问主题文件
  → 后续相关问题按索引召回
  → 用行动实验结果修订认识与演化记录
```

## 验收标准

1. 新主题模板的六个标题全部存在，且不含具体用户主题示例。
2. 契约明确要求事实/推断/建议区分、有依据的严肃审查、单一进行中实验和实质变化才记录演化。
3. 主项目、用户版变体和导出后的用户版契约保持完全一致。
4. 现有主题思考契约测试通过。
5. 使用“信息过载、最优解幻觉与不确定性”主题进行一次迁移验收：其内容可映射到六问结构，且只保留一个当前实验。

## 风险与处理

- **标题变得口语化但语义变模糊**：通过每部分职责和测试关键词固定边界。
- **严肃审查变成 AI 武断裁决**：要求审查给出依据、反例或风险；当前表达与用户确认仍优先。
- **单一实验导致复杂问题被过度简化**：未选中的行动保留为后续候选；当前只限制“进行中”的行动。
- **主项目与用户版漂移**：复用已有一致性测试和导出链路，不维护第二套文本。
