# 非模板日志输入适配与日反馈质量门设计

## 目标

让用户不必采用“开心的事情 / 充实的事情 / 思考 / 待改进”模板，也能稳定进入现有的“日志存档 -> 日反馈 -> 次日验证”链路；同时让分析深度服从输入证据，避免因材料不足而补全故事。

成功标准：

1. 明确以“日志 / 日记 / 记录一下 / 分析这篇日志”等自然语言提交的自由文本，可以稳定路由到 `log` skill。
2. 模板日志、自由叙事、列表片段和常见日期格式都能正确识别；日期不确定时不静默写入错误日期。
3. 日反馈内部按 A-D 输入证据等级降级：输入越弱，结论越克制；D 级先确认而不强行分析。
4. “日志质量”与“模板遵从度”分离，缺少固定栏目不再自动等于低质量。
5. 验证沉淀区分行为假说与干预实验；一次行动失败不直接证伪整个行为模式。
6. 主项目 `/journal-coach` 使用真正负责日志质量评分的 `journal-quality-coach`。

## 第一性原理

项目价值公式保持不变：

```text
价值 = (洞察质量 × 可行动性 × 闭环速度) / 使用摩擦
```

因此本设计遵守四条边界：

- 不要求用户为了触发 AI 而重写正文格式。
- 不新增一次模型调用或新的 intake agent。
- 不把“每段都填满”误认为高质量。
- 不用更丰满的输出掩盖输入证据不足。

## 架构

沿用现有三层，不新增代理：

```text
settings / review / log
        ↓ 识别意图、日期、单日/多日
journal-input contract
        ↓ 证据卡、A-D 等级、缺口处理
daily-analyzer
        ↓ 与等级匹配的洞察、动作和预测
daily-feedback / verified-patterns
        ↓ 保存与后续验证
```

新增 `.claude/shared/contracts/journal-input.md` 作为非模板日志输入的唯一运行契约。`log` skill 负责入口和存档，`daily-analyzer` 负责证据卡与分析，调用方仍负责保存反馈和写回验证沉淀。

## 入口识别

### 保证触发的输入

- 现有模板字段：`幸福日志`、`开心的事情`、`充实的事情`、`感谢的人`、`思考`、`待改进`、`ToDolist`。
- 明确日志前缀：`日志：`、`日记：`、`记录一下：`。
- 明确分析意图：`分析这篇日志`、`分析今天的日记`、`帮我看看这篇记录`。

不使用单独的“今天”“我觉得”“发生了”等高频词自动触发，避免把普通对话误存成日志。没有明确标记、但语义上可能是日志的长自由文本，由主代理只问一句是否作为日志存档分析。

### 日期识别

至少支持：

- `# 7月8日`、`# 7 月 8 日`
- `## 2026-07-08`、`2026/7/8`
- `幸福日志 7.8`、`日志 7.8`
- `今天`、`昨天`

识别到多个日期时走多日导入；只有一个日期时走单日；没有可靠日期时：

- 用户明确说“今天 / 昨天”时换算实际日期。
- 完全没有日期线索时，先确认日期，不再静默默认今天。

## 内部证据卡

分析前在上下文中临时提取，不创建中间文件：

```text
date: 日期及来源（explicit / relative / confirmed）
facts: 发生了什么、做了什么、结果是什么
states: 用户明确表达的感受、能量或身体状态
interpretations: 用户自己的解释、判断或疑问
intentions: 想保持、停止或尝试什么
previous_action_evidence: 对上一条行动的明确执行 / 未执行 / 不确定证据
gaps: 当前缺失且会限制结论的信息
```

不得把代理推断写入 `facts`、`states` 或 `previous_action_evidence`。

## A-D 输入证据等级

等级只供内部控制输出，不向用户显示评分：

| 等级 | 最小证据 | 输出能力 |
|---|---|---|
| A | 具体事实 + 明确状态 + 用户解释 + 行动意图或上一行动结果 | 完整日反馈；允许证据化模式连接 |
| B | 具体事实 + 状态或解释至少一项 | 一个核心洞察；跨日模式必须写成待验证假说 |
| C | 只有简短事实、情绪或片段，仍能确认是本人经历 | 只做镜像反射和一个维护闭环的小动作；不推断根因或长期模式 |
| D | 无法确认日期、本人经历或具体事件 | 暂不生成正式日反馈；只问一个最能补齐证据的问题 |

固定栏目、篇幅、文采和是否分享朋友圈不参与等级判断。自由叙事只要证据充分，同样可以是 A 级。

## 日反馈质量门调整

1. D2 洞察优先级改为：事实矛盾 -> 计划与行为差距 -> 自我评价与行为证据差距 -> 重复模式 -> 隐含动机假说。
2. 隐含动机没有用户自述或跨日证据时，只能写成“一个可能解释”，不得使用“根本不是……而是……”等定性句式。
3. C 级输入不输出 `🔗 和之前有关`；B 级跨日判断必须标注待验证。
4. 行动预测优先检查真实行为或结果，不要求下一篇日志必须出现某个固定栏目或措辞。
5. 缺少上一行动证据时保持 `⚠️ 证据不足`，不从“没有写”推导“没有做”。

## 验证沉淀调整

验证对象分为：

- **行为假说**：某种情境与行为 / 状态之间可能存在的关系。
- **干预实验**：闹钟、午休、发邀请等具体方法本次是否有效。

状态使用：

```text
待验证 / 部分支持 / 本次未奏效 / 多次支持 / 出现反例 / 证据不足
```

规则：

- 一次做到只记“部分支持”。
- 同一行为假说至少 3 次独立支持、覆盖至少 2 个日期或情境且没有强反例，才能进入“已确认的模式”。
- 一次没做到通常只说明干预“本次未奏效”；除非原预测明确是确定性命题，否则不直接写入“已证伪”。
- 明确反例记录为“出现反例”，后续根据重复证据修正或证伪假说。

## 日志教练边界

`/journal-coach` 评估两件不同的事：

1. **分析就绪度**：事实、状态、解释、行动 / 验证证据是否充分。
2. **六步法写作习惯**：是否使用事实回顾、重点筛选、感受、洞察、行动和外部交流。

六步法评分不再把固定栏目当必要条件；“分享讨论”是可选增强项，缺失时标注“未观察到”，不据此判断日志不可分析。

## 测试与验收

建立原生 PowerShell 回归脚本，不引入 Pester 依赖。覆盖：

- 模板、自由叙事、列表片段、非日志对话四类路由样本。
- 有空格中文日期、ISO、斜杠、点号等日期格式。
- A/B/C/D 契约存在且被 `log` 与 `daily-analyzer` 消费。
- 主项目 `/journal-coach` 正确路由到 `journal-quality-coach`。
- 主运行真相、用户版覆盖层和导出后的 `zhiji-user/` 关键文件一致。

首轮只验证规则与样本，不引入通用 NLP 分类器。只有真实内测出现稳定漏判后，才重新评估独立 intake agent。

## 非目标

- 不改变周报、月报、项目复盘的六问一级结构。
- 不改变输出目录与文件命名。
- 不自动把所有长文本识别为日志。
- 不重写用户原始日志为结构化模板。
- 不增加新的报告类型或评分展示。
