# 复盘自适应深度改造设计

## 目标

提高周报、月报和项目复盘的有效信息密度：让篇幅与证据强度、决策影响相称，减少为填满固定栏目而产生的重复、泛化和无效展开。

成功不以“报告更长或更自由”为准，而以以下结果为准：

- 重要结论仍可追溯到证据；
- 用户能看出本周期应保留、调整或停止什么；
- 后续行动仍有可检查方式；
- 无新增判断的栏目不再重复正文。

## 范围与非目标

本次只修改周报、月报、项目复盘及其共享综合契约和直接冲突的质量标准。

不修改年度复盘、人生设计、命令入口、工作流、路径、输出目录、报告文件格式或新增任何 agent、命令、配置和报告类型。现有六问一级标题、聊天摘要标记与周报用户回应区保持不变。

不以本次改造扩张自动化测试或新增评分体系。缺少真实复盘样本时，只验证运行契约与兼容性，不声称生成质量已经被真实样本证明提升。

## 方案选择

采用“六问作导航，判断驱动展开”的方案。

六问保留，因为它支持跨周期阅读、已有工作流摘要提取和“过去修正”与“未来规划”的职责分离。改变的是写作义务：从每个栏目都显式覆盖清单，变为每个关键判断必须满足质量门槛，栏目只有在存在新增、影响决策的信息时才展开。

不采用完全自由主题结构：它会破坏既有阅读与运行兼容性。也不只放松字数和条数：这不能消除栏目填充的根因。

## 写作规则

### 不可放松的质量门槛

1. 重要结论必须有日期、原文、结构化事实或输入视角证据；推断必须标记边界。
2. 对关键判断必须保留反例、限制条件或“证据不足”。
3. 方向锚点仍要做缺席检查，不得因主题归并而消失。
4. 后续行动必须由前述判断或根因推导，并包含适当的检查方式。
5. 缺材料时如实降级为部分复盘或数据不足，不补全故事。

### 可自适应的部分

1. 每个六问栏目可用一两句、合并同一主题下的相关事实，或明确写“无新增判断”。
2. 不再要求每个栏目逐项展示目标、感受、他人反馈、优势、偏差等所有子项；只有会改变结论的材料才写入。
3. 周报保留 1–3 个影响下周决策的判断，月报保留 2–3 个，项目复盘由项目复杂度决定，不设为了完整感的最低主题数。
4. 存在证据冲突、关键取舍、策略调整或高风险不确定性时展开；只是背景、重复证据或不改变行动的信息压缩或省略。
5. 质量自检只检查关键结论、行动和结构兼容性，不重复叙述正文。

## 实施边界

1. 先收敛共享 `review-synthesis` 契约，再让周报、月报、项目综合代理引用该契约，避免三处各自演化。
2. 只删除或改写与“栏目必填”有关的重复要求；不改变证据、验证、方向校准和摘要协议。
3. 同步修正与新契约直接矛盾的 `analysis-standards` 静态质量表述，避免旧标准反向诱导填表。
4. 用户版镜像和分发边界按既有导出流程同步，不手工制造运行漂移。

## 验收

### 必须通过

- 六问标题、YAML frontmatter、聊天摘要边界、报告路径及周报用户回应区保持兼容。
- 每个重要结论仍有证据或明确降级；下周期行动仍可检查。
- 周/月/项目契约不再要求为满足覆盖清单而重复正文或机械展开。
- 现有相关静态回归和分发边界检查通过。

### 不作为本次验收结论

- 没有真实输入对照时，不声称文风、洞察或用户满意度必然提高。
- 不以报告篇幅减少本身作为成功标准。

## 风险与回退

主要风险是“自适应”被误解为省略关键判断。以不可放松的质量门槛、方向缺席检查和行动检查方式防止该风险。

若真实样本显示关键事实、根因或行动被过度压缩，回退对应的可自适应规则，而不是恢复整套逐栏必填清单。
