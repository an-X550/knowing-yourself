# 桌面端 P2：周/月/项目复盘迁移 — 架构规格

> **状态：必要性闸门未通过（2026-08-14）。** 前置验收物（兼容矩阵、金样本、最小材料表）尚未准备，且无真实需求证据表明用户需要在桌面端做周期复盘。本文是待触发规格。

## 必要性闸门评估

| 闸门条件 | 当前状态 | 结论 |
|---|---|---|
| 1. 有当前、具体的问题证据 | 用户当前通过 Codex + `.claude/` 已能完整做周/月/项目复盘（PROJECT_STATUS 标记"已完成真实验收"）。桌面端尚未有用户表达"我想在桌面端做周报"的真实需求。 | **不成立** |
| 2. 直接服务核心目标 | 周期复盘是知己核心闭环的低频校准环节。桌面端迁移能服务"脱离 CLI 的低摩擦入口"目标，但周期复盘本身是低频操作，CLI 摩擦可接受。 | 成立但非当前瓶颈 |
| 3. 既有能力不能更简单解决 | Codex + `.claude/` 的周期复盘已"已完成真实验收"。桌面端迁移不能更简单地解决一个尚未出现的桌面端需求。 | **不成立** |
| 4. 实现后能立即验证 | 需要先准备周期复盘兼容矩阵、脱敏金样本和最小材料表。这些尚未准备。 | **不成立** |

**结论：闸门未通过。** 不接入图编排。先准备前置验收物。

## 真实问题定义

### 什么情况下才需要 P2

1. 用户在桌面端持续使用日反馈后，主动要求"在桌面端生成周/月/项目复盘"。
2. 用户发现每次做周期复盘都要切回 Codex CLI，产生了真实的切换摩擦。
3. 桌面端日反馈已积累足够样本（至少 4 周连续使用），支持周期复盘的材料读取。

### 什么情况下不需要 P2

- 日反馈垂直切片仍在积累真实使用样本 → 周期复盘缺少材料基础。
- 用户仍在 Codex CLI 中做周期复盘且无摩擦 → 不需要重复迁移。
- 没有金样本和兼容矩阵 → 不能宣称桌面端行为与 `.claude/` 规则对齐。

## 架构设计（获准后）

### 与日反馈 Runtime 的关系

```text
周期复盘 Runtime（独立图）
  ├─ build_period_evidence：读取下游沉淀物（日反馈、上次周期复盘）
  │    冲突或引用缺失时才读原始日志
  ├─ grade_period_evidence：A/B/C/D 分级
  │    D 级：返回补证问题，不调用模型
  ├─ generate_period_review：A/B/C 调用模型
  │    复盘六问、证据不足降级、单行动边界
  └─ END
```

- **不**复用日反馈图。周期复盘有独立的材料优先级、输出 Schema 和确认写入策略。
- **不**把现有 prompt 丢进 LangGraph。需要独立的兼容快照、材料选择和输出校验。

### 兼容快照

```ts
export const PERIODIC_REVIEW_COMPATIBILITY = Object.freeze({
  id: 'desktop-periodic-review-v1',
  sourceRuleVersion: '<待填，从 .claude/ 周期复盘规则版本获取>',
  runtimeReadsClaudeDirectory: false,
  materialCategories: [
    'daily-reviews',           // 目标周期内的日反馈
    'previous-periodic-review', // 上一次同类型周期复盘
    'project-snapshots',        // 相关项目的当前状态
  ] as const,
  supports: [
    'downstream-first material priority',
    'evidence-insufficient degradation',
    'review-six-questions',
    'confirmed write',
  ] as const,
  deferred: [
    'distribution',
    'reminders',
    'topic-thinking-integration',
  ] as const,
});
```

### 输出 Schema（框架）

周期复盘输出必须包含复盘六问的对应字段，经 Zod 校验。具体字段定义需要在金样本准备阶段确定。

### 权限边界

| 动作 | 策略 |
|---|---|
| 读取目标周期日反馈 | 自动，只读 |
| 读取上次周期复盘 | 自动，只读 |
| 读取相关项目状态 | 自动，只读 |
| 调用模型生成复盘 | 自动，显示材料类别 |
| 保存周期复盘 | 原子写入 + 复读验证 |
| 更新长期主题/画像 | 先展示差异，用户确认 |
| 读取原始日志 | 仅在冲突或引用缺失时 |

## 兼容矩阵扩展

| 已冻结规则能力 | 桌面端行为 | 验收测试 | 状态 |
|---|---|---|---|
| 下游沉淀优先 | 先读日反馈和上次周期复盘；仅冲突/引用缺失时读原始日志 | 待定 | 延后 |
| 证据不足降级 | 材料不足时返回补证问题，不生成复盘 | 待定 | 延后 |
| 复盘六问 | 输出 Schema 包含六问对应字段 | 待定 | 延后 |
| 确认写入 | 原子写入 + 复读验证；长期主题先展示差异 | 待定 | 延后 |
| 项目锚点 | 引用相关项目当前状态作为锚点 | 待定 | 延后 |

## 金样本要求

实施前必须准备：

1. 周期复盘兼容矩阵（逐项说明桌面端行为、规则来源和验收测试）。
2. 至少 3 个脱敏金样本：
   - 周复盘金样本（含 7 天日反馈 + 上次周复盘 + 期望输出）
   - 月复盘金样本（含 4 周日反馈 + 上次月复盘 + 期望输出）
   - 项目复盘金样本（含项目日志 + 上次项目复盘 + 期望输出）
3. 每个输出字段对应的最小材料表（哪个字段需要哪些材料）。

没有金样本不接入图编排。

## 获准后的最小实施范围

1. `periodic-runtime.ts`（独立 LangGraph 图）
2. `periodic-evidence.ts`（周期证据分级）
3. `periodic-review-v1.ts`（提示词 + 输出 Schema）
4. `GeneratePeriodicReview`（application 层）
5. UI：周期复盘页面（选择周期类型、生成、展示）
6. 兼容快照：`desktop-periodic-review-v1`
7. 隔离回归测试：periodic-runtime 不依赖 `.claude`

**不含**：主题思考集成、联网检索、分发、提醒、飞书、滴答。

## 停止理由

- 日反馈垂直切片刚完成 P0，真实使用样本不足，周期复盘缺少材料基础。
- Codex + `.claude/` 的周期复盘已"已完成真实验收"，没有真实桌面端需求。
- 提前迁移会复制未验证的兼容层，违反"先建立兼容矩阵和金样本"。

## 非目标

- 不把现有 prompt 丢进 LangGraph。
- 不复用日反馈图或泛化成通用 Agent loop。
- 不在周期复盘中集成主题思考或联网检索（属于 P3）。
- 不引入分发、提醒或外部集成。
