# README 补齐闭环提醒入口说明

## 目标

让维护者和最终用户都能准确理解现有闭环提醒的触发方式与边界，避免把它误解为后台定时催办或个人内容自动更新。

## 第一性原理

README 的作用是让正确读者以最低摩擦采取正确下一步，而不是复述实现细节。当前功能已存在两种触发：自然语言手动检查，以及成功新日反馈后的单次检查；文档必须说明这两种触发及“不自动写入”的边界。

## 范围与边界

- 修改主仓库 `README.md`：在闭环缺口能力条目中补充两个触发方式和非后台边界，仍以契约链接承载实现细节。
- 修改用户版源 `packaging/zhiji-user-overlay/README.md`：在统一入口与提醒说明附近明确“可随口询问”“长时间没有新日志时不会后台弹窗”。
- 运行导出脚本更新 `zhiji-user/README.md`。
- 不新增命令、提醒类别、定时器、状态文件、自动写入或运行逻辑。

## 验收标准

- 两份 README 都说明自然语言手动检查与成功日反馈后检查。
- 用户版明确：无新日志时不会后台催办；提醒不会自动修改个人内容。
- 用户版生成文件与 overlay 一致。
- 分发边界、项目完整性与 README 相关回归测试通过。

## 实施路径

1. 用最少文字补齐两个 README 的触发和边界说明。
2. 导出用户版。
3. 运行相关测试和全量检查，更新发布事实并创建本地提交；不推送。
