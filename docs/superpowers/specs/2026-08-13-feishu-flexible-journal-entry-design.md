# 飞书弹性日志入口设计

## 目标

让单用户飞书智能体能够安全处理常用的每日日志日期、标题和栏目格式，并允许用户不写 `日志：` 前缀；归档、日反馈与滴答截止日必须使用同一个确认后的日期。

## 第一性原理判断

真实问题是：日志文本已包含可验证的日期与结构信息，但飞书入口只接受一个前缀和一种标题日期，导致额外操作摩擦与错误归档。

- 已知事实：`幸福日志 8.10` 被错误地按消息接收日归档；本地 `log` skill 已定义多种明确日期头；日反馈契约已经允许自由叙事。
- 不可突破的约束：不能把普通聊天写入个人日志，不能从“昨天”“上周末”等相对表达猜测历史日期，不能把栏目名当作事实或心理结论。
- 取舍：只扩展可由正则与日历校验确定的高频格式；不能确认则回退到接收日（显式 `日志：` 入口）或返回用法提示（无前缀的普通消息）。

## 入口判定

保留原有 `日志：<正文>` 入口，并新增两种无需前缀的明确入口：

1. 正文首个非空行是“日志名 + 日期”：日志名允许 `幸福日志`、`日志`、`日记`、`复盘`，日期必须是本规格支持的确定性日期。
2. 正文首个非空行是确定性日期，且后续正文包含至少两个不同的已知栏目标题。

其他消息返回现有用法提示，绝不写入日志。无前缀入口没有明确或合法日期时也返回用法提示；只有显式 `日志：` 可以在正文没有日期时使用接收日兜底。

## 日期规则

仅检查正文开头的标题或独立日期行，不扫描长正文中的日期，避免把事件日期错当日志日期。

支持（可带 Markdown `#` 或 `日期：` / `日期:` 前缀）：

- `幸福日志 8.10`、`日志 8.10`、`日记 8.10`、`复盘 8.10`
- `2026-08-10`、`2026/8/10`、`2026年8月10日`
- `8-10`、`8/10`、`8.10`、`8月10日`

带年份的日期按该年份解析；未带年份的日期固定采用飞书消息接收年份。所有候选都必须通过日历校验。候选不存在、非法或超出首行范围时：显式前缀入口回退接收日；无前缀入口拒绝并提示用户使用明确日期或 `日志：`。

最终 `journal_date` 是唯一事实源：日志文件名、给 Codex 的 `Analyze YYYY-MM-DD` 提示、反馈文件名、反馈标题和滴答全天截止日（日期加一天）均复用它。

## 栏目线索

解析器仅生成给分析提示使用的“栏目线索”，不改变原文，也不创建第二套日反馈格式。栏目名以行首标题识别，允许 Markdown 标记与中英文冒号：

| 统一类别 | 可识别栏目 |
|---|---|
| positive_events | 开心的事情、好事、今日开心、收获 |
| progress | 充实的事情、完成了、进展、工作学习 |
| gratitude | 感谢的人、感恩、谢谢 |
| challenges | 待改进、烦恼、困难、问题、反思 |
| reflections | 思考、感受、随想、复盘 |
| intentions | ToDo、TODO、待办、明天要做、下一步 |

每个线索保留原栏目名与其下正文，直到下一个栏目或文本结束。未识别栏目、空栏目和自由叙事保持原样，不能被补全。

## 分析提示与输出

飞书工作流将原文、确认日期和可选栏目线索一并传给隔离的日分析会话。提示明确：原文是唯一证据，栏目只帮助定位；栏目线索不得替代证据、不得增加洞察数、不得把意图写成已完成事实。

`daily-analyzer` 与日反馈契约保持不变：一个主洞察、最多一个模式连接、一个五分钟以内的行动和一个可观察预测。输入不足时继续按 A-D 证据等级降级。

## 错误处理与可观测性

运行状态继续仅保存 message_id、处理状态、错误码和最终日期，不保存日志原文或分析内容。对日期回退新增规范错误码（如 `journal_date_invalid`）以便定位；用户回复不暴露内部错误细节。

## 验收

- 带 `日志：` 的合法日期格式均写入相应日期；非法日期回退接收日。
- 无前缀的“日志名 + 日期”格式可处理；无前缀的日期 + 两个栏目可处理。
- 单日期、普通聊天和一个栏目不足以触发无前缀归档。
- 栏目解析保留原文边界，识别英文 `ToDo`，自由叙事不受损。
- 分析提示同时包含确认日期、原文和栏目线索，且仍要求现有日反馈格式。
- 原有入口、幂等、目录边界、飞书分发与滴答参数测试保持通过；overlay 和 `zhiji-user` 导出包与主工作流一致。

## 已确认

用户于 2026-08-13 确认本设计；实现遵循“缺少年份按消息接收年份”的边界。
