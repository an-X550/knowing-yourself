# 知己桌面端 P0 数据透明与核心闭环设计

## 目标

让首次用户不读说明也能知道从哪里开始、数据实际存在哪里、备份包含什么，并完成“保存日志—生成反馈—原位阅读—周期复盘”。同时补齐用户明确要求的最小个人背景存储和恢复前业务校验。

## 范围与取舍

- 保留今天、复盘、项目、历史、设置五个一级入口，不新增第六页。
- 保留 Electron + React + TypeScript 模块化单体；Renderer 只通过类型安全 Preload/IPC 使用系统能力。
- 本轮实现：数据目录只读信息与打开入口、设置页分区、最小个人背景、备份业务 Schema 校验、条件式引导、日反馈/周期复盘原位结果、完整 Fake AI E2E。
- 本轮不实现：运行中修改数据目录、合并恢复、项目附件、自动画像、诊断中心、年报 UI、云同步、Tauri 或本地服务进程。

## 用户体验

侧栏底部的数据卡可点击并进入设置的数据区域。设置页分为“AI 服务”“数据与备份”“个人背景”：数据区持续显示真实绝对路径、可写状态、日志/复盘/项目/个人背景数量，提供“打开数据文件夹”，并明确备份包含内容数据和公开配置、不包含 API Key/缓存/诊断。

首次使用采用条件式引导，不新增欢迎向导：未保存 Key 时，今天页显示去设置的主行动；数据位置尚未确认时显示真实路径和打开入口。用户始终可以跳过 AI，只保存日志。确认状态只保存在 Electron `userData`，不得污染内容目录或备份。

今天页在生成成功后原位显示本次完整日反馈，仍提供历史入口；AI 失败不影响已保存日志。周/月复盘默认使用标准周期，“调整日期”后才展开日期字段；项目复盘继续显式选择项目和补充日期范围。生成成功后原位显示本次复盘正文和来源数。

## 数据与后端

新增 `DataDirectoryService`，只负责解析当前根目录、检查可写性、统计正式数据和通过 `shell.openPath` 打开已经解析的根目录；Renderer 不提交任意路径。当前根目录仍是 `%USERPROFILE%\Documents\知己` 或测试用 `ZHIJI_DATA_ROOT`，不提供运行时迁移。

新增最小 `ProfileRepository`，权威文件为 `profile/about-me.md`，字段仅包含 schemaVersion、正文、是否参与 AI 分析、createdAt、updatedAt。用户可查看、编辑、启用/停用和清空；不从日志自动推断。文件进入备份，API Key 仍只存在 Electron `userData/credentials.json` 且绝不导出。P0 只建立显式控制与迁移能力；将个人背景注入全部分析提示属于后续独立必要性评估，避免未验证地改变现有分析。

备份预览在 manifest、路径、大小和 SHA-256 通过后，必须继续解析每个 Journal、Review、Project、Profile 和公开设置文件，并校验项目引用与 Review sourceIds 指向包内或目标空目录中的正式对象。任何无效文件都在写入前拒绝。恢复仍仅允许空目录，通过 staging 写入、全量复读校验和原子切换；不做冲突合并。

## API 边界

- `dataDirectory.getInfo()` → 路径、可写状态、分类数量、总字节数、是否已确认。
- `dataDirectory.open()` → 成功或可执行错误；Main Process 固定打开当前根目录。
- `dataDirectory.confirm()` → 记录用户已看过当前路径。
- `profile.get/save/clear()` → 只返回公开 Profile，不返回任何凭据。
- 现有 `transfer.previewRestore()` 增加业务校验结果与 profile 数量。
- 日/周期生成接口继续直接返回 `Review`，Renderer 将返回值作为本次原位结果。

所有请求使用 Zod `.strict()`；错误必须能映射为“重试、去设置、打开目录或重新选择备份”等用户行动。

## 验收

自动化必须证明：真实路径与实际写入目录一致；打开目录只能使用后端根路径；个人背景可保存、停用、清空并进入备份；API Key 不进入备份；哈希正确但业务内容损坏的 ZIP 会在预览阶段被拒绝；用户可在今天页原位读到日反馈；周报默认不暴露日期、调整后才出现；Fake AI E2E 完成条件式引导、配置、个人背景、项目、日志、日反馈、周报、导出与空目录恢复。

Windows 安装、升级和卸载不在自动化结论中冒充人工验收；不运行安装程序以免影响当前电脑。
