# 事件驱动的闭环缺口提醒设计

## 真实问题

现有闭环缺口检查只能在用户主动询问“下一步/遗漏”或运行无参数 `/review` 时提供建议。它不是提醒：用户忘记询问时，即使 `current.md` 或其他沉淀物已被新证据推翻，也不会出现提示。

文件修改时间本身不能证明需要更新。真正有价值的信号是“新增且相关的证据已经出现，但相应沉淀物尚未承接”。

## 决策

在每次**成功生成新的日反馈**并完成既有验证沉淀后，执行一次已有的 `review-readiness-checker`。若检查器返回最高优先级建议，且同一候选未在最近 7 天内提示过，则在聊天中追加一行独立的非阻塞提醒。

不创建后台定时器、Stop hook 或全局关键词 hook；不自动更新 `current.md`、报告、画像或其他个人内容。自动写入仅限一份可丢弃的提醒投递状态，用于抑制重复提醒。

## 触发与不触发

| 场景 | 行为 |
|---|---|
| `/daily-review` 首次成功生成并保存日反馈 | 写回 `verified-patterns` 后检查并按需投递一条提醒 |
| 日志粘贴经 `log` skill 成功保存日反馈 | 写回 `verified-patterns` 后执行同一检查与投递 |
| 已有日反馈快路径展示 | 不检查、不提醒，避免重复查看时催办 |
| D 级输入、无日志、分析失败 | 不检查、不写状态 |
| 用户自然语言或无参数 `/review` | 仍直接返回检查器建议，但不写提醒状态 |

## 检查器与优先级

`review-readiness-checker` 仍是唯一的候选资格与优先级来源。它继续按既有顺序只选择一个候选：日反馈缺口、月/周/年复盘、当前上下文实质失真、日志质量抽样、人生设计信号。

其中 `current.md` 只有在最近 14 天存在至少 3 篇日期晚于其 `last_updated` 的日反馈，且至少一篇含当前焦点、待决事项、健康/关系或方向变化时才成立。文件年龄不能单独触发。

## 提醒投递状态

新增路径键 `output.readiness_delivery_state`，值为 `复盘/.readiness-delivery-state.md`。这是系统运行状态，不是用户个人沉淀，不应在聊天中展示，也不属于报告。

状态最多为每个候选类别保留一条记录：

```markdown
---
type: readiness-delivery-state
---

| candidate | signature | notified_on |
|---|---|---|
| current-context | current-last-updated:2026-07-20 | 2026-08-01 |
```

候选签名必须稳定，直到用户完成动作或候选目标改变：

- 日反馈缺口：最早缺失日反馈的日志日期；
- 周/月/年复盘：目标周期；
- 当前上下文：`current.md` 的 `last_updated`；
- 日志教练：最近教练报告日期，或 `none`；
- 人生设计：最近人生设计报告日期，或 `none`。

投递规则：

1. 没有同类同签名记录，显示提醒并写入当天日期。
2. 有同类同签名记录且距 `notified_on` 少于 7 天，静默抑制。
3. 同类签名改变，或相同签名已满 7 天，允许再次显示并更新记录。
4. 当前检查没有该候选时，删除该候选旧记录；动作完成后自然解除提醒。
5. 状态文件缺失或损坏时，按空状态重建；不得因此中断日反馈。

## 用户可见输出

日反馈正文和写入的 `output.daily_feedback` 必须保持既有格式，不嵌入提醒。仅在聊天展示日反馈之后，额外显示一行：

`🔔 提醒：{检查器的唯一建议}`

最多一行、最多一个建议；用户可以执行对应的手动命令，也可以忽略。系统不因忽略而修改任何个人内容。

## 实施与验证

1. 在共享路径中声明提醒状态文件，并新增简短投递契约，定义签名、冷却和损坏回退。
2. 让 `/daily-review` 和 `log` skill 在成功生成新日反馈与验证沉淀后调用同一投递契约；快路径、失败和 D 级输入明确跳过。
3. 将主定义同步至用户版 overlay，重新导出 `zhiji-user/`。
4. 新增契约测试，验证只有成功新日反馈触发、同签名 7 天抑制、签名变化/冷却到期重提醒、无候选清理、无个人内容写入、无 scheduler/hook。
5. 运行至少 3 次真实日反馈，记录提醒是否可执行、是否噪声、是否漏报；未出现重复证据前不改阈值或新增提醒渠道。

## 验收标准

- 用户不必主动询问，成功日反馈后仍能收到至多一条相关提醒。
- 重复查看旧日反馈不会触发提醒。
- `current.md` 不因单纯变旧而提醒。
- 同一未完成事项不会每天重复催办，7 天内被抑制。
- 无任何后台定时、Stop hook、自动报告或自动个人内容更新。
- 状态文件只服务提醒抑制；删除它不会损坏日志、反馈或沉淀物。
