# 桌面端 P4：模糊意图路由 — 架构规格

> **状态：必要性闸门未通过（2026-08-14）。** 当前桌面端所有入口均为确定性路由，无真实模糊入口失败样本。本文是待触发规格。

## 必要性闸门评估

| 闸门条件 | 当前状态 | 结论 |
|---|---|---|
| 1. 有当前、具体的问题证据 | 桌面端当前所有入口都是确定性的（日期选择、生成日反馈、日志列表等）。没有真实证据表明用户在桌面端使用模糊自然语言入口且现有入口不足。 | **不成立** |
| 2. 直接服务核心目标 | 模糊意图路由可降低使用摩擦，但当前桌面端入口已足够明确，摩擦不在意图路由上。 | 成立但非当前瓶颈 |
| 3. 既有能力不能更简单解决 | 当前所有入口都是确定性按钮/表单。没有模糊入口需要路由。 | **不成立** |
| 4. 实现后能立即验证 | 需要先收集真实模糊入口的失败样本（用户输入了什么、期望什么、现有入口如何失败）。尚未收集。 | **不成立** |

**结论：闸门未通过。** 不实现意图路由。等待真实模糊入口失败样本。

## 真实问题定义

### 什么情况下才需要 P4

1. 桌面端已实现多个工作流（日反馈 + 至少一个周期复盘或主题思考）。
2. 用户在真实使用中输入了模糊自然语言（如"最近有什么该补""关于刚才再展开"），且现有确定性入口无法满足。
3. 收集到至少 5 个真实模糊入口失败样本。

### 什么情况下不需要 P4

- 桌面端只有日反馈一个工作流 → 没有路由必要。
- 用户通过按钮/表单就能完成所有操作 → 没有模糊入口。
- 没有失败样本 → 不能验证路由是否解决了真实问题。

## 架构设计（获准后）

### 意图路由工作流

```text
用户输入自然语言
  → IntentRouter：先尝试确定性匹配（日期、关键词）
  → 确定性匹配失败：
      → 模型从注册工作流枚举中选择 WorkflowIntent
      → Zod 校验 WorkflowIntent
      → 校验通过：进入对应工作流
      → 校验失败：回退到澄清（"你想做 X 还是 Y？"）
  → END
```

### WorkflowIntent 枚举

```ts
type WorkflowIntent =
  | { type: 'daily-review'; date: string }
  | { type: 'weekly-review'; weekStart: string }
  | { type: 'monthly-review'; month: string }
  | { type: 'project-review'; projectId: string }
  | { type: 'topic-thinking'; topic: string }
  | { type: 'clarification'; question: string };
```

- 模型只能从注册表中选择，不能创建新工作流。
- Zod 校验失败即回退到 `clarification`。
- 不允许模型升级权限、创建工具或执行 shell。

### 权限边界

| 动作 | 策略 |
|---|---|
| 确定性路由 | 自动 |
| 模型选择 WorkflowIntent | 自动，但受 Zod 校验 |
| 创建新工作流 | 禁止 |
| 升级权限 | 禁止 |
| 执行 shell | 禁止 |
| 任意文件读写 | 禁止 |

## 兼容矩阵扩展

| 已冻结规则能力 | 桌面端行为 | 验收测试 | 状态 |
|---|---|---|---|
| 确定性路由优先 | 日期、关键词等已知意图先走确定性路由 | 待定 | 延后 |
| 模糊意图分类 | 模型从注册枚举中选择；Zod 校验 | 待定 | 延后 |
| 校验失败回退 | 回退到澄清，不猜测 | 待定 | 延后 |
| 禁止创建工作流 | 模型不能创建新流程、工具或权限 | 待定 | 延后 |

## 金样本要求

实施前必须准备：

1. 至少 5 个真实模糊入口失败样本（用户输入 + 期望行为 + 现有入口如何失败）。
2. WorkflowIntent Zod Schema 金样本（合法和非法各 3 例）。
3. 澄清回退金样本（校验失败 → 澄清问题）。

## 获准后的最小实施范围

1. `IntentRouter`（确定性路由 + 模糊路由）
2. `WorkflowIntentSchema`（Zod 校验）
3. `intent-router.test.ts`（确定性匹配、模糊匹配、校验失败回退）
4. UI：自然语言输入框（可选）
5. 隔离回归测试：intent-router 不依赖 `.claude`

**不含**：通用 Agent、shell、任意工具市场、模型自创流程。

## 触发条件

以下所有条件**同时满足**时，重新评估闸门：

1. 桌面端已实现至少 2 个工作流。
2. 收集到至少 5 个真实模糊入口失败样本。
3. 现有确定性入口确实无法覆盖这些模糊入口。

## 停止理由

- 当前桌面端只有日反馈一个工作流，没有路由必要。
- 提前实现意图路由会为未验证的需求引入模型决策点，增加漂移风险。
- 确定性入口已足够覆盖当前操作，摩擦不在意图路由上。

## 非目标

- 不实现通用 Agent 或 Agent loop。
- 不给模型 shell、任意文件读写或递归扫描能力。
- 不引入工具市场或 MCP marketplace。
- 不允许模型创建新工作流、工具或权限。
