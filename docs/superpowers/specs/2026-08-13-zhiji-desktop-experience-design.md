# 知己 Windows 客户端体验增强设计

## 1. 第一性原理结论

真实问题不是界面“不够漂亮”，而是不会使用 CLI、Skill 或 Agent 的用户无法快速理解下一步，也无法从界面确认数据是否安全保存、AI 是否正在工作、生成内容来自哪里。首要价值是降低首次配置、每日记录和周期复盘的决策摩擦；视觉质量必须服务这条闭环，同时让项目具备可信的前端/全栈简历展示价值。

已知事实：当前 Electron MVP 已有今天、复盘、项目、历史、设置五个入口，核心领域能力和 Windows 安装包可用；当前 Renderer 由少数大组件和单行 CSS 构成，缺少导航选中态、明确的加载/空状态、正式项目创建交互、历史筛选与窄窗口适配。

约束：继续使用 Electron、React、TypeScript 和本地 Markdown/JSON；不让 Renderer 接触 Node、文件系统、API Key 或网络；不修改 `.claude/` 产品逻辑；不引入大型 UI 组件库；不以主题切换、图表、复杂动画或移动端稀释核心闭环。

## 2. 方案选择

采用“轻量设计系统 + 关键交互重构”。不只覆盖旧 CSS，也不引入完整第三方组件库。通过小型可复用组件、设计变量和明确页面状态获得主要收益，控制依赖、包体积和维护成本。

视觉定位为“安静、可信的本地复盘工作台”：温和米白背景、深墨绿色导航、有限的青绿色强调色、清晰的文本层级和克制阴影。界面应像成熟生产力工具，而不是数据大屏或聊天机器人。

## 3. 信息架构与应用壳

固定侧栏保留五个入口：今天、复盘、项目、历史、设置。每项包含图标、文字和可见选中态；底部展示“仅保存在本机”和 API 配置状态。主内容区使用统一页头，支持标题、说明和页面主操作。窗口宽度低于 860px 时侧栏收窄为图标栏，内容仍可使用；第一版不做手机响应式。

Renderer 拆分为：

- `AppShell`：导航、页面容器和全局状态区域。
- `PageHeader`、`Button`、`Field`、`StatusBanner`、`EmptyState`、`Modal`：无业务数据的展示组件。
- Today、Reviews、Projects、History、Settings：各自持有页面状态和业务调用。
- `useAppData`：集中加载并刷新 journals/projects/reviews/settings 的轻量 hook，不把正式数据放入 Zustand。

## 4. 核心页面

### 今天

编辑器是第一视觉焦点。页头展示自然语言日期和本地保存提示。日志卡片包含项目选择、写作提示、字符数、保存状态和明确主按钮。保存成功后才显示绿色确认；失败保留正文并显示可重试错误。日反馈成为相邻的第二阶段卡片，解释材料来源、生成状态和取消动作。最近记录仅展示三条，点击进入历史。

### 复盘

采用四段流程：选择复盘类型、选择范围与项目、预览材料、确认生成。周报/月报提供合理的默认日期范围；项目复盘可选项目并补选日期。材料预览显示数量、日期、摘要和来源类型。只有预览有效时才启用生成；材料变化后旧预览立即失效。结果保存成功后提供“去历史查看”。

### 项目

以正式 Modal 替代 `window.prompt`。项目卡显示状态、关联日志数和最近活动日期；归档是二级动作并要求页面内确认，不删除日志。空状态直接提供新建项目入口。

### 历史

采用左侧列表、右侧阅读区。支持日志/日反馈/周报/月报/项目复盘类型筛选、日期文本筛选和项目筛选。选择条目后显示 Markdown 风格正文、日期、项目和来源 ID。无结果时解释当前筛选条件，而不是空白。

### 设置

服务商使用三张选择卡。API 地址仅在自定义接口时编辑；Key 永不回显，使用“已安全保存”状态标识。测试连接与保存分离，结果使用可访问状态提示。页面解释 HTTPS/本机 HTTP 边界以及数据目录，不暴露绝对敏感路径。

## 5. 交互和可访问性

- 所有异步主操作具备 idle/loading/success/error 状态；加载时防止重复提交。
- 状态反馈使用 `aria-live`，Modal 支持 Escape、遮罩关闭、初始焦点和焦点环。
- Button 明确 primary/secondary/ghost/danger 变体；归档等操作不与主操作同色。
- 所有表单输入都有可见 label、帮助文本和错误文本；禁用态不仅依赖颜色。
- 使用 CSS 变量定义颜色、字号、间距、圆角、阴影和过渡；尊重 `prefers-reduced-motion`。
- 不引入网络字体、远程图片或外部图标包；图标使用本地内联 SVG 组件。

## 6. 后续能力优先级

界面完成后按以下顺序继续：

1. `.zhiji.zip` 备份与恢复：直接降低本地优先产品的数据丢失顾虑，用户价值高。
2. 核心 Electron E2E：覆盖配置假接口、创建项目、写日志、生成日反馈、周期复盘和历史查看，证明主要旅程可用。
3. Windows 安装包冒烟与发布事实：不静默安装当前电脑；自动检查打包内容，人工安装矩阵保持未验证，直到真实执行。
4. 流式文字增量：改善等待感，但不改变结果正确性，排在备份和验收之后。
5. 自动更新、Windows 10 虚拟机矩阵和跨平台：投入大、当前证据不足，继续暂缓。

## 7. 测试与完成标准

- 组件测试覆盖导航选中态、Modal 创建项目、异步状态、复盘预览门、历史筛选和设置 Key 不回显。
- 既有领域/集成测试保持通过，生产依赖高危/严重漏洞为零。
- Electron E2E 使用本地假 OpenAI 接口和隔离数据根，不调用真实模型、不读取个人日志。
- Windows x64 安装包继续输出到 D 盘；构建下载可临时使用 npmmirror 或腾讯镜像，不永久修改全局 npm 配置，不使用华为云。
- `.claude/` 下既有 Skill、Agent、命令和工作流无产品逻辑变更，项目三组回归继续通过。

## 8. 明确不做

本轮不做移动端、云同步、账号系统、SQLite、团队协作、图表仪表盘、主题市场、自动更新、遥测、在线字体和后台常驻进程。ZIP 恢复只处理本产品允许列表中的数据与公开设置，不包含 API Key、诊断日志或缓存。
