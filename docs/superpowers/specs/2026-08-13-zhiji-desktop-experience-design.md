# 知己 Windows 客户端任务型首页与体验收敛设计

## 1. 结论与设计依据

当前客户端的问题不是缺少功能，而是前端按“今天、复盘、项目、历史、设置”等模块组织，用户必须自行推断先做什么、功能之间如何衔接。Skill 入口更清楚，是因为它直接描述“我想完成什么”。本轮不增加更多业务能力，而是把既有日志、反馈、周期复盘、项目、历史与数据管理能力组织成一条可见任务链：

```text
记录经历 → 得到反馈 → 查看记录 → 周/月/项目复盘
```

采用已经确认的“主次分明”开始页：一个由本地数据确定的建议动作，加三个低权重能力入口。视觉与交互借鉴 Apple 产品的克制、清晰层级、渐进披露和原位反馈原则，但不复制 macOS 外观，也不使用“Apple 风格”掩盖信息架构问题。

本设计替代本文旧版中的以下决定：

- 原“今天、复盘、项目、历史、设置”五入口改为“开始、日志、复盘、项目、设置”。
- 独立历史页退出一级导航；日志历史归入日志，复盘历史归入复盘。
- 旧深绿侧栏原型不再是强制视觉基线，仅保留已有可复用组件和安全边界。
- 不新增行动状态模型、自然语言聊天入口、统计仪表盘或新的后端服务。

## 2. 目标、约束与验收标准

真实目标：用户打开软件后，无需理解 Skill、Agent、文件结构或后端模块，也能立刻知道软件能做什么，以及当前最值得做什么。

不可突破的约束：

- 继续使用 Electron、React、TypeScript 和本地 Markdown/JSON。
- 保留 Renderer、Preload、Main Process 的权限隔离，不让 Renderer 访问 Node、文件系统、API Key 或任意网络。
- 不修改或替换现有 `.claude/` Skill、Agent、命令和工作流。
- 不增加大型 UI 组件库、云服务、账号、遥测或新的数据存储系统。
- 首页判断只读取已加载的本地数据，不调用 AI，不猜测用户意图。

首版验收标准：

1. 新用户打开软件后，10 秒内能回答“软件能做什么”和“我现在该做什么”。
2. 推荐任务最多两次点击即可开始。
3. 一级导航仍为五个，不因增加首页而膨胀。
4. 每页只有一个高强调主操作，低频选项按需展开。
5. 日志、反馈、项目、备份和密钥的既有后端行为保持不变。

## 3. 信息架构

```text
开始
├─ 唯一建议下一步
└─ 做复盘 / 查看记录 / 管理项目

日志
├─ 写今天的日志
└─ 过去日志

复盘
├─ 周报 / 月报 / 项目复盘
└─ 历史复盘

项目
└─ 项目与关联日志

设置
├─ AI 服务
├─ 数据与备份
└─ 个人背景
```

“历史”不是用户目标，而是日志与复盘的阅读状态，因此不再占用一级入口。开始页只负责选择任务和呈现状态，不复制日志编辑器、复盘表单或项目业务界面。

### 3.1 开始页

开始页包含四个操作区域：

1. 日期和一句短欢迎语，不显示营销文案。
2. 一张“建议下一步”主卡，包含建议、透明原因和唯一主按钮。
3. 三个低权重入口：做复盘、查看记录、管理项目。
4. 一行本地状态：数据已保存在本机，以及 AI 是否配置；点击数据状态进入设置的数据分区。

不在首页展示统计图、连续打卡、资讯流、备份按钮、个人背景、模型参数或全功能宫格。

### 3.2 日志页

日志页的主任务是记录今天。页面默认聚焦编辑器，项目关联保持可选。一个主按钮表达完整结果：有 AI 时为“保存并生成今日反馈”，没有 AI 时为“保存日志”；“仅保存”降为次级操作。

今日反馈生成后原位展示。过去日志置于编辑区之后或独立的次级视图中，按日期选择阅读；不混入周报、月报和项目复盘。

### 3.3 复盘页

复盘页保留周、月、项目三种类型和“预览材料 → 确认生成”的安全链路。标准周/月日期默认收起，用户选择调整时才展示。生成结果原位显示。

历史复盘作为该页的次级视图，读取日反馈、周报、月报和项目复盘；不再要求用户进入独立“历史仓库”。

### 3.4 项目页

项目页只描述实际能力，统一使用“项目与关联日志”，不再称“项目与材料”。从项目详情发起复盘时携带项目 ID，复盘页自动选择该项目；用户仍可修改日期范围和项目。

### 3.5 设置页

设置页顶层标题统一为“设置”，内部为 AI 服务、数据与备份、个人背景三个清晰分区。自定义 Base URL、备份恢复详情等低频内容默认按需展开。既有密钥安全存储、真实数据路径、打开目录、备份校验和个人背景文件机制不变。

## 4. 建议下一步的确定性规则

新增纯前端 `next-step` 规则模块。输入为当前日期、日志列表和复盘列表，输出稳定的建议类型、原因文案和导航意图。

优先级固定如下：

```text
1. 今天没有日志
   → 写下今天的经历

2. 今天已有日志，但没有对应的今日反馈
   → 生成今日反馈

3. 今天日志和今日反馈均已完成，且处于周末，本周至少有 3 篇日志
   → 做本周复盘

4. 其他情况
   → 查看最近记录
```

规则约束：

- “周末”首版定义为星期六或星期日；该定义集中在规则模块中，避免散落页面。
- “本周至少 3 篇日志”是透明的首版材料门槛，不读取内容质量，不调用模型。
- 如果已经存在覆盖当前周的周报，不再次推荐本周复盘，回落到“查看最近记录”。
- 当前没有可靠的行动完成状态，因此不推荐“验证上次行动”，也不从 Markdown 文本猜测待办。
- 首页显示推荐原因，例如“今天还没有记录”或“日志已保存，还差一次今日反馈”。
- 用户可忽略建议，直接使用三个次级入口。
- 日志保存或复盘生成成功后刷新应用数据，首页建议随之重新计算。

## 5. 导航意图与组件边界

现有仅传递页面 ID 的导航扩展为页面 ID 加可选意图。意图是短生命周期的 UI 状态，不写入本地业务文件。

首版支持：

- `journal.compose`：进入日志页并聚焦编辑器。
- `journal.generate-daily`：进入日志页并将生成反馈作为当前主操作。
- `review.weekly`：进入复盘页并默认选择本周复盘。
- `review.project`：进入复盘页并携带项目 ID。
- `records.journals`：进入日志页的过去日志视图。

开始页不得直接调用保存、生成、归档或恢复接口。它只计算下一步并导航，由既有业务页面继续负责表单、异步状态、错误和结果。

建议的 Renderer 边界：

- `StartPage`：展示推荐和三个能力入口。
- `resolveNextStep`：无副作用纯函数。
- `NavigationTarget`：页面和可选意图的类型契约。
- `JournalPage`：由当前 Today 页面演进，组合编辑与日志历史。
- `ReviewsPage`：组合复盘生成与复盘历史。
- `AppShell`：只负责五项导航、当前页面和全局本地状态。

Main Process、Preload 和现有 IPC 无需为开始页新增接口。

## 6. 视觉与交互规则

- 页面只保留一个主标题、一句必要说明和一个主操作。
- 只有当前建议与当前页面主操作使用强调色。
- 次级能力使用低对比卡片或文字按钮，不与主操作竞争。
- 使用接近 Windows 系统字体栈、清晰字号层级、稳定间距和充足留白；不引入网络字体。
- 不使用大面积渐变、数据大屏、连续弹窗、营销横幅、多彩功能图标或装饰动画。
- 页面和状态过渡控制在 150–200ms，并尊重 `prefers-reduced-motion`。
- 操作结果在原位置显示；成功后不强迫用户跳转寻找结果。
- 空状态只回答“为什么为空”和“下一步做什么”。
- 日期调整、自定义接口和恢复详情使用渐进披露。
- 图标继续使用本地内联 SVG，颜色不能成为表达状态的唯一方式。

视觉稿选择记录：采用“B · 主次分明”，即一个主要建议加三个低权重能力入口；不采用只露出一个动作的极简版，因为它无法充分解决“看不出有哪些能力”的已知问题。

## 7. 数据流与失败处理

开始页数据流：

```text
useAppData 读取 journals / reviews / projects / settings / dataDirectory
→ resolveNextStep 计算建议
→ StartPage 展示原因和导航动作
→ 用户进入既有业务页面
→ 业务成功后 refresh
→ 返回开始页时重新计算
```

失败边界：

- 应用无法读取本地数据时，不展示可能错误的推荐；沿用全局读取失败页和重试动作。
- AI 未配置时，日志页仍允许保存；开始页状态明确显示“AI 尚未配置”，但不使用阻塞式向导。
- 生成失败不改变已保存日志，错误在日志页原位提供重试或进入设置。
- 周报材料不足时，复盘页说明缺少多少日志，并允许返回日志页；首页不会在未达到 3 篇门槛时推荐周报。
- 导航意图消费后即清除，刷新页面不应重复触发聚焦或自动操作。
- 首页只突出操作，不自动保存、自动生成或自动打开系统目录。

## 8. 测试与验证

### 8.1 纯函数测试

覆盖四条优先级规则，以及：

- 今天日志存在但日反馈属于其他日期。
- 周末材料达到和未达到 3 篇。
- 当前周报已存在时不重复推荐。
- 日期跨周和星期日边界。

### 8.2 组件与导航测试

- 一级导航始终为开始、日志、复盘、项目、设置五项。
- 开始页只有一个 primary 操作和三个次级能力入口。
- 建议原因与规则结果一致。
- 从开始页进入日志时聚焦编辑器或突出生成反馈。
- 从项目页发起复盘时自动带入项目。
- 日志历史不显示周期复盘；复盘历史不显示原始日志。
- AI 未配置仍可保存日志。

### 8.3 核心 E2E

使用 Fake AI 和隔离数据目录验证：

```text
开始页显示“写下今天的经历”
→ 进入日志并保存
→ 开始页更新为“生成今日反馈”
→ 生成并原位查看反馈
→ 返回开始页，建议按日期与材料规则更新
```

既有项目、历史读取、备份恢复、密钥隔离、类型检查和 Lint 测试继续通过。

### 8.4 最小用户验证

实现后使用 3–5 位不了解 Skill 的目标用户执行四个任务：开始写日志、生成今日反馈、寻找周复盘、指出数据位置。记录完成率、首步犹豫和点击数；没有重复证据前不增加新入口或新推荐类别。

## 9. 实施顺序与明确暂缓

按收益和依赖顺序实施：

1. `resolveNextStep`、导航目标类型和测试。
2. 开始页与五项导航。
3. 日志页合并过去日志、复盘页合并历史复盘。
4. 项目复盘携带上下文，设置页与术语收敛。
5. 核心 E2E 和最小陌生用户任务测试。

明确暂缓：行动状态与验证跟踪、自然语言输入框、智能推荐模型、统计图、连续打卡、年报、人生设计、主题思考、云同步、账号系统、Tauri 重写、后端服务、复杂全局状态库和纯装饰动画。

这些能力只有出现具体、重复且可验证的用户证据，并且不能通过现有页面或规则更简单解决时，才重新进入必要性评估。
