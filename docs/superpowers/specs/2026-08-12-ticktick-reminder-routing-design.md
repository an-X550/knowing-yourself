# 滴答清单纯提醒路由设计

## 结论

所有纯提醒——无论一次性还是周期性——默认创建为滴答清单任务。Codex 定时任务不再作为默认提醒通道；只有用户明确指定 Codex 时才允许例外。需要到点读取文件、生成报告或执行其他工作的请求不属于纯提醒，必须单独评估，不能借提醒规则自动执行。

## 第一性原理依据

用户真正需要的是在正确时间收到可靠通知并自行决定是否开始复盘，而不是让 AI 调度器代替用户复盘。当前证据是：Codex 本地定时派发在应用运行、电脑唤醒以及完整重启后的受控测试中仍未送达；滴答官方能力已成功创建原生周重复任务，并返回任务 ID、时区、提醒和重复规则。首次滴答真实通知仍需等 2026-08-16 19:00 验证，不能提前宣称送达成功。

因此最小路径是复用滴答已有的通知与重复能力，不新增后台服务、脚本、系统定时器或重试队列。Codex 继续承担对话和复盘生成入口，不承担默认可靠调度。

## 路由规则

1. 用户要求“提醒我”“到点通知我”等纯提醒时，默认直接创建滴答任务。
2. 一次性提醒传绝对日期或时间、`Asia/Shanghai` 和到点提醒；周期提醒额外传原生重复规则。
3. 提醒内容只描述用户需要手动开始的动作，不读取项目文件、不生成复盘、不调用飞书分发。
4. 用户明确指定 Codex 定时任务时，可按其要求使用 Codex，但必须说明该通道此前存在本地派发失败证据。
5. 需要自动执行工作的请求退出本规则，重新判断必要性、权限、运行环境和验收方式。

直接创建的提醒不进入报告结果分发状态，也不改变四类报告行动的字段限制、确认门、判重和完成判断。滴答仍只允许 create-task 写入，不为提醒读取、搜索、更新或删除任务。

## 最小修改范围

- 在 `AGENTS.md` 与 `CLAUDE.md` 增加唯一的提醒路由入口，并保持逐字一致。
- 在结果分发契约增加“直接纯提醒”的窄边界，同步 overlay 和用户版。
- README 只增加一条用户可见说明；PROJECT_STATUS 记录当前能力、失败证据和待验证项。
- 将仍会指导执行的旧 Task 8 标记为 Codex 试点失败并由滴答方案取代，不翻修其他历史 spec/plan。
- 在现有 PowerShell 契约测试中增加防回退断言，不新增服务、依赖或运行命令。
- 暂停现有 `automation-2`，避免未来与滴答周提醒重复；以自动化工具实际返回为验收依据。

## 不做什么

- 不开发新的调度器、守护进程、hook、后台队列或定时扫描。
- 不自动运行 `/weekly-review`，不读取日志，不生成周报。
- 不扩展报告结果分发的来源白名单或任务内容字段。
- 不批量改写只具历史记录价值的旧文档。
