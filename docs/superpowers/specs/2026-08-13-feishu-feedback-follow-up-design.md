# 飞书日反馈追问设计

## 目标

在手机看到“知己”每日反馈后，用户可在同一飞书私聊中自然地追问某个洞察；不把机器人扩张为通用聊天，也不改变日志、反馈和滴答闭环。

## 第一性原理判断

真实问题是跨平台切换中断了短暂但真实的反思动机，不是缺少一个通用 AI 对话产品。

- 已知事实：飞书入口已经能接收日志、生成并回复每日反馈；用户明确表示偶尔想继续追问而不想切换平台。
- 不可突破的约束：日志和反馈是本地权威数据；普通聊天不能被悄然保存；追问不能触发滴答、飞书文档导入、验证沉淀或修改历史材料；不能引入会话历史与长期记忆。
- 取舍：一次追问只围绕一份每日反馈和必要的同日日志，牺牲“像网页端无限聊天”的体验，换取低实现/维护成本、可解释上下文与隐私边界。

## 入口与宽松识别

仅接受已绑定用户的文本私聊。监听器按以下优先级路由：日志入口优先，其次才是追问入口，避免一篇日志被错当聊天。

以下任一方式均是明确追问：

1. 显式引导词开头：`追问：`、`想问：`、`问：`、`关于刚才`、`展开说说`、`为什么`、`那我该怎么做`、`我还是不懂`。
2. 自然引导词开头的短追问，例如 `为什么？`、`关于刚才，展开说说`。
3. 消息中明确引用反馈日期，例如 `问 8月10日那条：…`、`关于 2026-08-10 的反馈…`。

无前缀的普通聊天不调用模型，返回简短帮助；入口帮助与每一条日反馈的最终回复都显著展示：

```text
💬 想继续聊这条反馈？发送“追问：你的问题”，也可直接写“为什么？”或“关于刚才，展开说说”。
查看旧反馈可写：“问 8月10日：你的问题”。追问不会改写日志、创建任务或保存聊天记录。
```

## 上下文选择

每次追问无状态运行：

1. 从用户文本优先提取确定性日期，复用日志入口的年月/数字/中文日期规则；缺少年份按消息接收年份。
2. 没有日期时，选取本地 `复盘/每日反馈/` 目录中最近修改的一份有效每日反馈。
3. 必须读取目标每日反馈；同日 `日志/YYYY-MM-DD.md` 存在时一并读取，作为补充证据。
4. 目标反馈不存在时回复明确帮助，不调用 Codex。

追问问题是原始消息去除可选引导词后的文本；为空时回复用法提示。不存在跨请求的聊天状态、上下文累积、自动检索或写入。

## 模型与回复

使用现有隔离、只读、固定模型的 Codex 调用方式。提示包含：目标日期、反馈原文、可选同日日志和用户问题，并要求：

- 以给定材料为证据，区分事实、推断和建议；材料不足时说明证据不足。
- 直接回答问题，默认不超过 300 中文字；只有问题要求展开且证据足够时才适当加长。
- 不生成新的正式日反馈，不凭空续写分析，不自动给任务；若自然需要行动，最多给一个可选的小实验。
- 不写文件、不调用飞书、滴答或其他外部工具。

成功回复正文后固定附加追问帮助。失败仅回复规范错误码与重试提示；不持久化消息正文、回答正文或会话。

## 可靠性与安全

- 保持发送者白名单、私聊、文本限制和 `message_id` 防重。
- 为追问记录最小状态：message_id、状态、目标日期和错误码；不记录问题、原文、回答或回复关系。
- 追问处理不进入结果分发，也不写日志/反馈目录；测试以文件哈希证明零副作用。
- 当前适配器不保存机器人回复消息 ID，因此不承诺“直接回复机器人消息”的绑定语义；“刚才”与无日期追问统一按本地最近反馈处理。

## 验收

- 每日反馈最终消息和使用提示都清楚说明追问功能及两种用法。
- `追问：`、自然引导词、日期引用、有效回复引用都能进入追问；日志入口仍优先。
- 无日期时正确选择最近反馈；日期格式和非法日期处理与日志入口一致。
- 不存在目标反馈、空问题、普通闲聊时不调用 Codex。
- 追问 Codex 提示仅包含目标反馈、可选同日日志和问题，并明确只读、无副作用与证据边界。
- 追问前后日志、反馈、分发状态文件哈希不变；原有日志、分发和用户版边界测试继续通过。
- overlay 与 `zhiji-user` 工作流保持逐字一致。

## 已确认

用户于 2026-08-13 确认本设计，并确认若实现需要会话状态、复杂平台集成或明显高维护成本，则应停止而非扩张。本实现未触发该条件。
