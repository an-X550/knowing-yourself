# 桌面端 P3：主题思考与受控联网 — 架构规格

> **状态：必要性闸门未通过（2026-08-14）。** 依赖 LangGraph 持久化（暂停/恢复），当前 Runtime 使用 MemorySaver（内存），不支持应用关闭后恢复。且无真实需求证据。本文是待触发规格。

| 闸门条件 | 当前状态 | 结论 |

**结论：闸门未通过。** 不引入 SQLite checkpointer，不实现暂停/恢复，不注册联网工具。

## 架构前置条件

### 为什么 P3 需要暂停/恢复

主题思考的既有契约是"首次讨论不写入、确认后才沉淀"。这意味着工作流需要在"讨论"和"确认沉淀"之间暂停，等待用户输入。如果应用在此期间关闭，需要能恢复到暂停点。

当前日反馈 Runtime 使用 `MemorySaver`（内存检查点），应用关闭即丢失。这不满足主题思考的需求。

### 何时评估 SQLite checkpointer

根据架构设计文档："这一切片需要应用关闭后的暂停/恢复，届时才评估 LangGraph 持久化与 SQLite checkpointer；不要为了 P1 或 P2 提前引入它。"

评估条件：
1. P3 闸门通过（有真实桌面端主题思考需求）。
2. MemorySaver 无法满足暂停/恢复需求。
3. SQLite checkpointer 能嵌入 Electron Main Process，不启动独立服务。
4. 打包体积、升级成本和权限面可接受。

如果 SQLite checkpointer 不可行，备选方案是文件系统检查点（JSON 状态序列化到 `runtime/` 目录），但需要单独 spec。

## 真实问题定义

### 什么情况下才需要 P3

1. 用户在桌面端持续使用日反馈后，主动要求"在桌面端做主题思考"。
2. 用户发现每次做主题思考都要切回 Codex CLI，产生了真实的切换摩擦。
3. 桌面端已有足够的基础设施（暂停/恢复、确认写入）支持高影响操作。

### 什么情况下不需要 P3

- 日反馈垂直切片仍在积累使用 → 主题思考缺少上下文基础。
- 用户仍在 Codex CLI 中做主题思考且无摩擦 → 不需要重复迁移。
- 没有暂停/恢复能力 → 不能安全实现"确认后才沉淀"。

## 架构设计（获准后）

### 主题思考工作流

```text
用户提出主题相关问题
  → read_thinking_index：匹配已有主题索引
  → 有匹配：read_selected_topics(max=2)
  → 讨论：模型在受限上下文内生成讨论首稿（不写入）
  → interrupt：暂停，等待用户
  → 用户确认沉淀：
      → propose_topic_update：展示差异
      → await_user_approval：用户明确确认
      → commit_topic_update：原子写入 + 复读验证
  → 用户不确认：结束，不写入
  → END
```

### 受控联网工具

| 工具 | 输入 Schema | 副作用 | 用户确认 |
|---|---|---|---|
| `web_search` | `{ query: string, domains?: string[], recency?: string }` | 只读外部搜索 | 用户显式请求后执行 |
| `read_web_source` | `{ sourceId: string }` | 只读指定来源 | 用户可见来源 URL |

- 联网只在用户明确请求时注册和执行。
- 搜索结果在 UI 中显示来源 URL 和日期。
- 搜索结果不自动写入长期认识或本地文件。
- 任何沉淀仍要求用户确认。

### 权限边界

| 动作 | 策略 |
|---|---|
| 读取 thinking_index | 自动，只读 |
| 读取最多 2 个相关主题 | 自动，只读 |
| 生成讨论首稿 | 自动，不写入 |
| 提议主题更新 | 自动，展示差异 |
| 确认沉淀 | 用户明确操作 |
| 联网搜索 | 用户显式请求 |
| 写入主题文件 | 原子写入 + 复读验证 + 用户确认 |
| 浏览任意 URL | 禁止 |
| 执行网页脚本 | 禁止 |

## 金样本要求

实施前必须准备：

1. 主题索引脱敏样本（含至少 3 个已有主题）。
2. 讨论首稿金样本（输入问题 + 匹配主题 + 期望讨论输出）。
3. 确认沉淀金样本（差异展示 + 用户确认 + 写入结果）。
4. 联网搜索金样本（用户请求 + 搜索结果 + 来源展示 + 不自动沉淀）。

## 获准后的最小实施范围

1. LangGraph 持久化评估（SQLite checkpointer 或文件系统检查点）
2. `topic-runtime.ts`（独立 LangGraph 图，含 interrupt 节点）
3. `thinking-index.ts`（主题索引只读仓储）
4. `web-search-tool.ts`（受控联网工具，Zod Schema）
5. UI：主题讨论页面（讨论首稿 + 确认沉淀 + 来源展示）
6. 兼容快照：`desktop-topic-thinking-v1`
7. 隔离回归测试：topic-runtime 不依赖 `.claude`

**不含**：自动主题提取、向量检索、跨设备同步、任意 URL 浏览、网页脚本执行。

以下所有条件**同时满足**时，重新评估闸门：

1. 桌面端日反馈已连续使用至少 4 周。

3. LangGraph 持久化（暂停/恢复）评估完成且有可行方案。

## 停止理由

- 主题思考是高影响操作，需要暂停/恢复能力。当前 Runtime 不具备。
- 提前引入 SQLite checkpointer 会为未验证的需求增加打包成本和运维面。
- Codex + `.claude/` 的主题思考已有完整契约，没有真实桌面端需求。

## 非目标

- 不为 P1 或 P2 提前引入 SQLite checkpointer。
- 不给模型任意 URL 浏览或网页脚本执行能力。
- 不自动从日志或讨论中提取主题。
- 不让搜索结果静默沉淀为长期认识。
