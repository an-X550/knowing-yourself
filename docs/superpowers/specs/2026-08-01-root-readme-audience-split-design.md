# 根 README 读者分流重构设计

**日期**：2026-08-01  
**状态**：已确认，待实施  
**范围**：仅 `README.md`

## 问题

根 README 同时承担维护者入口、完整产品说明和最终用户教程，重复了 `zhiji-user/README.md` 的大量内容。读者无法快速判断应从哪里开始，且两份说明会持续产生漂移成本。

## 决策

根 README 的主要读者是维护者与潜在贡献者；最终用户的完整使用说明以 `zhiji-user/README.md` 为唯一入口。

## 内容结构

1. **首屏定位**：保留项目目标、最小成功标准和核心闭环，说明根仓库与用户版的职责边界。
2. **维护者入口**：说明运行真相在 `.claude/`，给出维护者最短了解路径；将首次使用用户导向 `zhiji-user/README.md`。
3. **能力概览**：用紧凑功能地图展示已有能力，不展开终端用户操作步骤、主题思考说明、角色契约或完整示例。
4. **维护与分发**：保留用户版导出命令、同步流程、项目结构和权威文档导航。

## 明确不做

- 不改变任何产品逻辑、命令、路径、分发边界或用户版内容。
- 不新增功能、文档入口或配置。
- 不在根 README 复制用户教程；用户操作细节仍只在 `zhiji-user/README.md` 维护。

## 验收

- 根 README 明确区分维护者与最终用户入口。
- 读者可从根 README 找到运行真相、用户版、导出流程与核心治理文档。
- 所有本地 Markdown 链接有效，版本徽章与 `VERSION` 一致。
- README 不再包含完整的最终用户操作教程或与用户版重复的长篇功能解释。
