# 主题思考更新整合设计

## 目标

用户确认沉淀一条新认知时，维护的是一份可独立阅读的当前论证，而不是向既有文章追加内容。整篇不设字数或固定标题数量；篇幅只由理解当前判断所需的事实、约束、反例与行动决定。

## 已确认的问题

现行契约要求比较后决定“保留、修正、替换、合并、归档或不写入”，但没有要求更新后重建当前判断和全文逻辑链。因此模型可能把正确的新内容局部追加到错误的位置，留下重复论据、已失效的行动或历史判断与当前判断混杂。

## 方案选择

采用“整篇论证重组”而非新增模板、固定篇幅、额外确认或全量主题审计。

每次确认更新时，AI 先把新认知判为补强、修正、反驳、分支、行动变化或不写入；再确定更新后的当前问题、当前判断与受影响的章节。它可改写、移动、合并或删除旧内容，历史变化只保留必要差异在观点演化记录中。

写入前进行四项全文检查：

1. 事实、推断、价值取舍和未知仍共同支持当前判断；
2. 同一理由不在多处重复，旧判断不伪装成当前判断；
3. 新认知带来的反例、代价或分支位于实际影响判断的位置；
4. 当前行动、验证、等待或转向仍由更新后的判断与约束推出。

任一项不成立时，继续重组或决定不写入；不得以新增行动、标题或解释填补缺口。

## 边界

- 不读取、写入或修改用户主题正文作为产品改动；真实样本只在本次回放中脱敏描述。
- 不增加用户填写、确认、重生成、workflow、入口、默认读取范围或自动写入。
- 不改变首次讨论契约；本次只影响用户确认后的更新。
- 不要求文章短，也不为显得完整保留无助于当前论证的历史内容。

## 验证

使用已授权、具有 2026-07-30 新认知记录的私有主题作一次回放。由于仓库没有写入前快照，审计记录必须明确：旧稿根据该主题的演化表与新增来源重建，不能声称是原始历史版本。

回放只评估四项全文检查和是否引入用户成本；静态测试只用来防止契约/镜像漂移，不能作为体验改善的证明。若回放没有明显改善，不发布本轮改动。
