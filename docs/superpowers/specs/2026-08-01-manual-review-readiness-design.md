# 手动复盘时机检查设计

## 要解决的问题

现有 `review-readiness-checker` 定义了有用的检查规则，但没有被明确接入 Codex 自然语言入口或 `/review`。结果是用户需要复盘时机建议时，规则可能根本不会执行。

## 决策

将“我现在该更新什么”“我该做什么复盘”等同类的语义请求，以及无参数 `/review`，统一路由至同一个 `review-readiness-checker`。示例不是固定口令：只要用户在问“现在是否有该补齐、更新或复盘的下一步”，就应进入该检查。该检查只读取必要材料、只返回优先级最高的一条建议，且不生成报告、不修改 `current.md`、不写入任何运行数据。

## 入口与边界

| 入口 | 行为 |
|---|---|
| `/review`（无参数） | 调用 `review-readiness-checker` |
| Codex 自然语言询问“最近有什么该补？”“我有遗漏吗？”“是不是该复盘了？”等下一步检查意图 | 读取同一命令与 agent，执行相同检查 |
| 明确日期、周/月、项目或人生设计请求 | 维持原有路由，直接执行用户指定的分析 |

不新增后台定时器、关键词 hook、状态文件或自动写回。时间只能作为既有检查规则中的辅助信号，不能单独触发写入。

明确要求日期、周期、项目或人生设计分析时，直接走既有对应路由；普通闲聊、泛泛建议和单次情绪表达不触发本检查。

## 输出契约

检查器最多输出一条不超过 80 字的建议；候选优先级为月度复盘、周度复盘、年度回顾、强/弱人生设计提醒、日志教练、无需建议。输出只能是建议文本或空字符串，禁止附加分析、执行确认、文件路径或自动操作。

## 验证

新增契约测试覆盖：自然语言触发词被路由；路由明确指向 `/review` 和检查 agent；两个入口均禁止生成报告或写入；检查器保留“一条最高优先级建议”和“无建议为空”的约束。用户包由现有导出流程同步，并通过完整性测试验证。
