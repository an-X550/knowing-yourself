# 用户版飞书 AI 部署同步设计

## 目标

让 `zhiji-user` 具备与主项目相同的单用户飞书每日反馈入口，或在所选 AI 后端不是 Codex 时，提供足以让执行型 AI 完成最小适配与部署的指令。

## 第一性原理

需要迁移的是稳定能力，不是维护者的个人环境。用户版应包含事件监听、日志分析契约、本地落盘、飞书沉淀、滴答创建和防重逻辑；open_id、目录 token、project_id、凭证、状态、UU 远程偏好和真实验收记录必须由每位用户独立产生。

AI 只负责“日志正文 -> 每日反馈 Markdown”。飞书导入和滴答创建继续使用确定性、受限工具；更换 Claude、DeepSeek 或其他 API 时只替换分析适配器，不重写分发链路。

## 文件边界

- `shared`：本地飞书监听工作流、无敏感配置示例，与主项目逐字节一致。
- `override`：用户版 README、本地入口说明，以新用户部署为目标，不含维护者个人状态。
- `user_only`：用户版 AI 部署手册，提供平台人工授权点和可复制执行指令。
- 不导出：运行配置、状态、日志、复盘、个人画像、凭证和远端对象 ID。

## 验收

1. overlay 和导出后的用户版包含监听工作流、配置示例、入口说明和 AI 部署手册。
2. 共享工作流固定 Codex 日分析为 `gpt-5.4`、只读临时会话，并以 `codex login status` 预检而不调用模型。
3. 部署手册覆盖飞书、滴答、Codex、Claude、DeepSeek、人工授权点、凭证边界和脱敏端到端验收。
4. 导出边界与项目完整性测试通过；两个仓库均不跟踪个人运行数据。
