## 1. 背景与闸门证据

`docs/2026-08-14-r2-evidence-grading-comparison.md` 已完成 R2 证据采集，结论：

- 桌面端 `daily-evidence.ts` 正则判级与 Skill 语义判据分歧 **3/5**。
- **S2（最严重）**：短小第一人称评价被正则判 D → 触发 D 级熔断，用户得不到反馈、只收到补证问题。核心高频闭环被打断。
- S3 跨 2 级（C vs A）、S4 差 1 级（B vs A）：只影响反馈深度，不影响反馈有无。
- 根因：自由叙事的判断句式不依赖"因为/所以/我发现"等连接词，关键词面与语义判据不同构。

**必要性闸门四项核对**：

| 项 | 结论 |
|---|---|
| 1. 当前、具体的问题证据 | 有：3/5 分歧，含 1 条 D 级误熔断实样 |
| 2. 服务核心目标 | 是：日志→日反馈是产品存在的高频理由 |
| 3. 现有能力无法更简单解决 | 是：纯扩关键词只修 5 个已知样本，新句式仍漏 |
| 4. 实现后可立即验证 | 是：金样本回归测试 |

**本轮明确不做**（防止范围蔓延）：

- A/B/C 级精度对齐（只影响深度，记为已知差异登记进兼容矩阵）。
- 月报深度、`/yearly-review`、`/life-design` 桌面复刻（属开发路线图后续阶段 B/C，见 `docs/2026-08-14-desktop-development-roadmap.md`，本轮不做）。
- 打包链无关改动。

### 2.2 技术决策（推荐方向，开工报告时确认）

**D 路径语义兜底（混合方向）**：

- 正则前置门保持不变：A/B/C 快路径零额外成本，不回退既有行为。
- 仅当正则判 **D** 时，经既有 `ProviderPort` 追加一次低成本语义复核，zod strict schema 约束输出（四要素布尔 + 本人经历布尔）；复核确认存在本人经历则保守提升至 **C**（不直接跳 A/B，避免过度修正）。
- 复核失败、超时或未配置 Provider：回落原 D 判定，不阻塞、不产生反馈。
- 成本预估：D 级样本是少数路径，每至多一次短调用；远低于"全部样本过模型"的方案。

**被否决的替代**（供复核时对照，不必重议）：

- 纯扩关键词：只修已知 5 样本，泛化差，R2 已证关键词边界与语义不同构。
- 全量语义判级：每个日志多一次调用，违背 D 级省钱设计，性价比不成立。

### 2.3 工作项

**WI1 金样本回归集（先做，TDD 红测）**

- 把基线 5 条样本 + 从 `日志/` 新选 ≥5 条真实非模板自由叙事（脱敏：去人名昵称）固化为单元测试 fixture。
- 新样本必须至少包含：2 条"短小第一人称评价"（D 误熔断高发形态）、2 条含疑问式解释、1 条模板日志（防回归误伤）。
- 断言每条的期望判级与"是否生成反馈"。此时新测试应为红。

**WI2 D 路径语义复核实现（TDD 转绿）**

- 在 `daily-evidence.ts` 或相邻处实现复核入口；Provider 交互复用既有端口与测试替身，禁止新增真实网络依赖。
