# 模型选择建议

> 适用范围：本项目内以 `model: inherit` 运行的各类 agent / workflow。  
> 这份文档总结的是当前仓库提示词结构下的经验性建议，不是绝对结论。若要为你自己的日志语料做最终判断，建议使用“同输入 A/B/C 对比”验证。

## 先说结论

- 想要最稳的最终质量：优先使用 Claude 系模型，尤其是周复盘、月复盘、年复盘和 life-design。
- 想要结构清晰、项目复盘干净：GPT-5.5 通常也很合适，尤其适合 `/project-review`、`/weekly-review`、`/monthly-review`。
- 想要更低成本、更快批量跑：DeepSeek V4 Pro 可以承担 `/daily-review`、`/journal-coach` 或草稿版复盘，但在长链路综合任务上波动通常更大。

## 为什么不同模型会有差别

本项目多个核心 agent 使用的是 `model: inherit`，也就是继承调用方模型，而不是把模型写死在 skill 里。  
因此，模型差异会直接影响以下几个能力：

- 长上下文整合：能不能把多天、多周、多份报告压缩成少量高质量主题。
- 证据纪律：会不会老实区分“有证据的结论”和“证据不足的假设”。
- 中文反思语境：能不能在中文日志里抓到微妙的自我叙事、回避和反证。
- 克制力：会不会写成空话、鸡汤、顾问腔，或者过度自信地下判断。
- 行动压缩：能不能把建议落到短周期、可验证、低摩擦的实验。

## 模型风格概览

| 模型 | 整体印象 | 更适合 | 主要风险 |
|------|------|------|------|
| Claude 系 | 长文综合、中文语感、边界感通常最稳 | 最终版日分析、周/月/年复盘、life-design | 成本通常更高，速度未必最快 |
| GPT-5.5 | 结构清晰、分解能力强、项目表达利落 | 周复盘、月复盘、项目复盘、统一入口 `/review` | 有时会偏“咨询顾问风”，太整齐、略少生活感 |
| DeepSeek V4 Pro | 性价比高、日常调用友好 | 日分析、批量草稿、低成本试跑 | 长链综合和抽象校准任务波动更大，易重复或泛化 |

## 各功能建议

| 功能 | 任务特征 | 优先推荐 | 可接受备选 | 不太建议直接做最终版的情况 |
|------|------|------|------|------|
| `/daily-review` | 单日、短输出、强约束 | Claude 系 / GPT-5.5 | DeepSeek V4 Pro | 几乎都能用，主要差在稳不稳 |
| `/weekly-review` | 7 天归并、要做缺席检查和交叉验证 | Claude 系 | GPT-5.5 | DeepSeek 更适合先跑草稿 |
| `/monthly-review` | 长上下文、多视角归并、主题压缩 | Claude 系 | GPT-5.5 | DeepSeek 不建议直接做最终月报 |
| `/project-review` | 目标、过程、决策、协作复盘 | GPT-5.5 / Claude 系 | Claude 系 / GPT-5.5 | DeepSeek 更适合初稿，不适合高要求交付 |
| `/yearly-review` | 跨月报告整合、时间跨度长 | Claude 系 | GPT-5.5 | DeepSeek 不建议做最终版年复盘 |
| `/life-design` | 抽象程度最高，要区分重力问题与可设计问题 | Claude 系 | GPT-5.5 | DeepSeek 不建议直接做最终版 |
| `/journal-coach` | 多日质量评估、趋势观察 | GPT-5.5 / Claude 系 | DeepSeek V4 Pro | 对“长期卡点”提醒要求高时优先 Claude / GPT |
| `/review` | 智能路由入口，实际质量取决于被路由任务 | 跟随目标任务 | 跟随目标任务 | 不单独讨论 |

## 如果你只想记一条简单规则

### 低成本日常使用

- `/daily-review`：Claude、GPT、DeepSeek 都可用。
- `/journal-coach`：可优先考虑 GPT 或 DeepSeek 做日常批量检查。

### 重要复盘与最终留档

- `/weekly-review`
- `/monthly-review`
- `/project-review`
- `/yearly-review`
- `/life-design`

以上更建议优先用 Claude 系；如果你更在意结构化表达与项目语言，`/project-review` 可以优先考虑 GPT-5.5。

## 按任务目标选模型

| 你的目标 | 建议 |
|------|------|
| 要最终质量最稳 | Claude 系 |
| 要结构特别清楚 | GPT-5.5 |
| 要低成本高频跑 | DeepSeek V4 Pro |
| 先批量筛一遍，再精修 | DeepSeek / GPT 先跑，Claude 收口 |
| 要验证哪个最适合自己的日志 | 用同一批日志做 A/B/C 对照 |

## 推荐的实际调用策略

### 方案 A：单模型稳定使用

- 全部用 Claude 系。
- 适合希望“少折腾、直接稳定”的使用者。

### 方案 B：双模型分工

- 日常 `/daily-review`、`/journal-coach` 用 DeepSeek 或 GPT。
- `/monthly-review`、`/yearly-review`、`/life-design` 用 Claude 收口。

### 方案 C：先草稿后定稿

- 先用 DeepSeek 或 GPT 跑出草稿。
- 再把同一批输入交给 Claude 做最终版。
- 适合在成本、速度和质量之间折中。

## 如何做“同输入 A/B/C 对比”

不要只凭印象判断哪个模型更好。更稳妥的做法是：

1. 选一批完全相同的日志输入。
2. 固定 skill、上下文、模式和时间范围。
3. 分别用 Claude、GPT、DeepSeek 各跑一遍。
4. 并排比较以下维度：

- 是否引用到了真实证据
- 是否能识别关键模式，而不是复述日志
- 是否有重复解释或套话
- 是否会过度自信地下结论
- 行动建议是否短、具体、可验证
- `life-design` 是否真的区分了重力问题、可设计问题和伪问题

如果你最终要把结果长期留档，以“同输入对比后的稳定性”优先，而不是单次惊艳感。
