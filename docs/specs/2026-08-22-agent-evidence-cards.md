# Agent 本地证据卡片需求文档

## 1. 产品定位

知己桌面端是面向 LLM / Agent 应用工程岗位的作品集项目。真实日常复盘仍可由 Skill 承担；桌面端重点证明 Agent Runtime、上下文管理、Function Calling、本地证据检索、安全工具边界和 Electron 产品化能力。

本需求不把知己扩展成通用 Agent 平台。它只补齐一个当前可观察缺口：Agent 已能调用 `zhiji.memory.search`，但用户只能看到“检索完成”，不能直接核实命中的本地记录。

## 2. 目标用户问题

当用户询问过去经历、反复问题或项目状态时，Agent 应：

1. 自动检索本地权威记录；
2. 展示使用了哪些日期、类型和摘录；
3. 区分事实、归纳和已验证模式；
4. 在需要判断或下一步时给出一个可验证行动；
5. 未命中时明确说没有找到证据，不凭印象补完。

核心成功场景：

> 当我询问过去的经历、反复出现的问题或某个项目状态时，Agent 能从日志和复盘中找到带日期的真实证据，明确说出证据边界，并在适用时给出一个可在后续日志中验证的行动。

## 3. 新功能必要性闸门

| 判据 | 当前证据 |
|---|---|
| 具体问题 | Agent 页只显示工具活动标签；最终回答是否基于真实命中无法由观看者直接核实 |
| 核心或面试叙事 | 直接证明本地检索、结构化工具结果、安全边界和可解释 Agent 产品化 |
| 更小替代 | 只靠 persona 要求模型引用证据仍可能遗漏或改写；普通测试不能提供用户可见来源 |
| 可立即验证 | 使用固定脱敏数据运行三条演示问题，可直接检查卡片日期、类型、摘录、冲突处理和行动边界 |

四项成立，允许进入 Spec。最小实现是复用现有 `memory.search` 结果增加只读 UI 事件和卡片，不新增检索引擎、存储或权限。

## 4. 范围

### 4.1 本期包含

- 历史语义明显时，Agent persona 继续要求优先调用现有 `zhiji.memory.search`；不新增宿主意图路由。
- Main Process 校验后的 `memory.search` 结果以结构化事件送到 Renderer。
- Agent 页展示本次回合的只读证据卡片。
- 卡片展示记录类型、日期、有限脱敏摘录。
- 日志和复盘命中在已有安全导航能力允许时提供跳转；已验证模式无合适详情页时只展示，不制造新页面。
- 卡片不持久化；会话重启后仍保留原对话正文，但不恢复历史证据卡片。
- 使用脱敏、可公开的固定演示数据验证三条场景。

### 4.2 本期不包含

- SQLite FTS5、BM25、embedding、向量数据库、混合检索或重排；
- MCP Client、MCP Server 或外部 Memory Provider；
- 图片、音频、视频输入；
- Computer Use、Shell、任意文件或浏览器控制；
- 自动写入记忆、用户画像或第二份日志真相；
- 展示隐藏 chain-of-thought、`reasoning_content` 或完整内部执行轨迹；
- 证据卡片持久化、跨会话同步或新的备份格式；
- 新的 hash、baseline、冻结 contract 或发布 gate；
- 把当前词法检索称为 RAG。

## 5. 证据权威顺序

| 层级 | 来源 | 用法 |
|---:|---|---|
| 1 | 日志原文 | 事实发生与用户原始表述的最高依据 |
| 2 | 日/周/月/项目复盘 | 对原始记录的阶段归纳，必须允许回到来源 |
| 3 | 已验证模式 | 用户确认后的跨期结论，仍不能覆盖冲突的日志事实 |

发生冲突时，Agent 必须回到日志原文，指出冲突，不允许让 AI 复盘静默覆盖原始记录。

项目当前状态由 `projects.list` 提供；涉及历史项目经历时，再结合日志与复盘证据。项目列表不是长期记忆副本。

## 6. 交互规则

### 6.1 自动检索

涉及“以前、最近、一直、反复、某项目”等历史信息时，Agent 应优先使用本地检索，不要求用户每次输入“搜索记忆”。首版继续依赖 Agent persona 和 Function Calling，不新增启发式意图分类器。

若模型没有调用工具，不展示伪证据卡片；回答也不得声称“根据记录”。

### 6.2 卡片内容

每次成功的 `memory.search` 结果形成一组卡片：

| 字段 | 规则 |
|---|---|
| 类型 | 显示“日志”“复盘”或“已验证模式” |
| 日期 | 使用工具结果中的日期；未知时显示“日期未知” |
| 摘录 | 使用 Main Process 已校验、已限长、已脱敏的摘录，不让模型重新生成 |
| 跳转 | 只接受既有安全导航目标；无法映射时不显示按钮 |

默认展示前 3 条，命中超过 3 条时允许在本组卡片内展开，最多展示工具现有上限 8 条。不增加“修改”“删除”“写入记忆”等操作。

### 6.3 回答与行动

- 事实查询：只回答事实、日期和证据边界，不强制生成行动。
- 模式、原因、判断或下一步：引用证据后最多给出一个可验证行动。
- 没有命中：明确说明未找到匹配记录，可提出一个缩小时间、项目或关键词范围的补证问题。
- 证据冲突：列出冲突双方，以日志原文为事实依据。

### 6.4 生命周期

- 卡片属于当前 Renderer 运行态，不写入 DSH JSONL。
- 切换会话时只显示当前运行期间属于对应会话的卡片；不得串到其他会话。
- 删除会话时清除对应运行态卡片。
- 重启应用后卡片不恢复；最终回答中的事实和日期仍保留在会话正文。

## 7. 安全与隐私

- 数据仍从现有日志、复盘和已验证模式仓储读取，不建立第二份记忆库。
- Utility Process 不直接读取文件；结果继续经过 Main Process 的 Zod 校验和 `safeText`。
- Renderer 只接收有限摘录和安全标识，不接收绝对路径、原始 URL、API Key 或仓储对象。
- 卡片不能绕过现有写入确认门。
- 演示使用脱敏数据；真实私人日志不进入公开截图、录屏、仓库或简历附件。

## 8. 演示数据

提供一组可公开的固定夹具，至少包含：

- 三个不同日期的日志；
- 一份引用其中日志的周期复盘；
- 一个用户已确认的验证模式；
- 一处复盘归纳与日志原文不一致的可识别冲突；
- 一个可在后续记录中检查的行动结果。

优先复用现有 repository 测试夹具和隔离临时数据目录。若现有 E2E 没有可复用初始化入口，只增加测试/演示专用夹具加载方式，不向正式用户界面增加“导入演示数据”入口，也不覆盖正常数据目录。

## 9. 验收场景

### 场景 A：事实查询

用户询问某次历史事件发生时间。

- Agent 调用本地检索；
- 卡片展示正确日志日期和摘录；
- 最终回答与卡片一致；
- 不生成行动建议。

### 场景 B：模式查询

用户询问某个问题是否反复出现。

- Agent 检索多条记录；
- 卡片至少展示两个不同日期的相关证据；
- 回答区分事实与归纳；
- 最多给出一个能在后续日志中检查的行动。

### 场景 C：冲突查询

用户询问一个被复盘错误归纳的历史判断。

- 卡片同时展示日志和复盘证据；
- 最终回答明确指出冲突；
- 日志原文优先，不静默采用复盘结论。

## 10. 工程验收

- 共享事件 Schema 拒绝未知字段、超长摘录和非法类型。
- Main Process 只转发 `memory.search` 的安全结果，不转发原始仓储对象。
- Renderer 按会话隔离卡片，默认 3 条、最多 8 条，可展开。
- 跳转只使用已有白名单导航目标。
- 工具失败或空命中不会生成误导性卡片。
- Agent Page、Dispatcher、Runtime 和相关 Schema 的普通单元测试通过。
- 全量测试、typecheck、lint、package 和既有 E2E 在实施阶段按当前项目流程验证。

## 11. 简历表述边界

可以写：

> 在 Electron 桌面 Agent 中接入 DSH Runtime 与 DeepSeek Function Calling，通过 Main Process Zod 契约和权限边界检索本地日志/复盘证据，并以用户可核实的证据卡片展示来源；正式写入继续经过领域服务与确认流程。

不能写：

- 自研 RAG 或向量数据库；
- 完整语义长期记忆；
- MCP 工具生态；
- 通用 Computer Use；
- 自主递归改进。
