# Agent 本地长期记忆检索 Spec

## 目标

让 Agent 在用户询问“我以前记录过什么”“过去某段时间是否出现过某模式”时，能够从知己已有的权威数据中先做一次有限、可解释、只读的召回，再决定是否调用现有 `journals.get` / `reviews.get` 获取摘要。

## 不做什么

- 不新建 `MEMORY.md`、用户画像库或第二份日志真相。
- 不自动抽取、自动保存或自动修改记忆；所有正式日志和验证模式仍走原有用户意图、确认和仓储链路。
- 不引入 embedding、向量数据库、外部记忆 SaaS、MCP server 或网络请求。
- 不把关键词检索宣称为语义理解；结果不足时 Agent 必须说明“未检索到匹配记录”。

## 工具契约

工具名：`zhiji.memory.search`

输入：

```json
{
  "query": "字符串，1-200 字符",
  "limit": "可选整数，1-8，默认 8"
}
```

输出：

```json
{
  "kind": "memory.search",
  "hits": [
    {
      "id": "journal_xxx | review_xxx | pattern_xxx",
      "kind": "journal | review | pattern",
      "date": "YYYY-MM-DD 或 null",
      "excerpt": "有限脱敏摘要"
    }
  ]
}
```

输入和输出都经过共享 Zod schema。`limit` 只控制结果数，不允许扩大摘要长度或读取范围。

## 数据源

| 来源 | 召回字段 | 输出日期 |
|---|---|---|
| 日志 | `body`、日期、项目关联 ID（只用于匹配） | 日志日期 |
| 复盘 | `body`、类型、周期、项目 ID（只用于匹配） | 周期结束日 |
| 已确认验证模式 | `statement`、`evidenceSummary` | 创建日期 |

所有读取复用现有 repository/service 的 `list()`，不直接拼接文件路径，不绕过 Schema。

## 排序与摘要

1. 对查询做 trim、大小写归一和有限的中英文短语切分。
2. 完整短语命中优先；其次按命中词数量排序。
3. 分数相同时按日期从新到旧，再按稳定 ID 排序，保证同一数据集结果稳定。
4. 摘要从首个命中位置附近截取有限窗口；没有命中位置时从正文开头截取。
5. Dispatcher 再执行既有 `safeText`，任何路径或 URL 命中都被省略。

该排序不是质量基线，也不加入 hash/gate；它只是让 Agent 获得可解释的第一阶段召回。未来有真实规模证据时，可在同一服务接口后替换 SQLite FTS5 或外部 provider，而不改变 Agent 工具契约。

## 安全与生命周期

- 工具只读；AbortSignal 在工具桥中仍可取消。
- 不返回绝对路径、原始 URL、凭证、文件内容的无限长度版本。
- 不允许 Agent 通过该工具写入记忆或更改日志。
- 搜索失败沿用现有中文工具错误；空结果是正常结果，不伪造“记得”。

## 验收

- 关键词可命中日志、复盘和验证模式三种来源。
- 空查询、超长查询、超范围 limit、未知字段在 Main Process 被拒绝。
- 路径/URL 内容不会跨工具桥泄露。
- Agent Runtime 的工具列表包含该工具；工具回合能正常回传给模型。
- 全量测试、类型检查、lint、打包和既有 E2E 不回归。
