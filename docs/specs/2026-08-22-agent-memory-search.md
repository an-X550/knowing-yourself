# Agent 本地中文历史检索 Spec

## 1. 目标

让 Agent 在用户以自然中文询问“以前发生过什么”“某种问题是否反复出现”时，从知己已有的日志、复盘和已确认验证模式中完成有限、可解释、只读的词法召回，再按需调用现有 `journals.get` / `reviews.get` 获取完整摘要。

本 Spec 不把当前能力称为 RAG，也不承诺完整语义记忆。它解决两个已经能从代码确定的失败：

1. 当前正则会把连续中文查询当成一个完整词项，自然长问题只要没有原句复现就可能零命中；
2. “任务定得太大”与“行动拆解”这类有限同义表达缺少受控候选查询入口。

## 2. 第一性原理与最小成熟方案

### 2.1 当前机制为什么不足

现有 `termsOf()` 使用：

```text
[a-z0-9]+ | 连续中文字符+
```

因此“我以前是不是经常把任务定得太大”基本会成为一个长中文词项；记录中即使存在“把行动拆成更小步骤”，也不会命中。现有测试只覆盖“行动”单关键词，不能证明自然中文问题可用。

### 2.2 采用方案

优先复用成熟组件，不自研 BM25：

- 使用 [MiniSearch](https://github.com/lucaong/minisearch) 的内存全文索引、BM25+ 排序、字段存储和自定义 tokenizer；MiniSearch 本身无传递依赖；
- 使用运行时标准能力 `Intl.Segmenter('zh-CN', { granularity: 'word' })` 产生 word-like 词项；
- 对连续 CJK 文本补充二元词片，降低分词差异和短词漏召回；
- 精确短语继续获得显式加权；
- DeepSeek 工具参数允许提供至多 3 个候选查询，用于有限同义改写；候选查询只影响召回，不作为事实写入上下文；
- 每次搜索从现有 repository/service 的最新数据在内存中重建索引，不新增 SQLite、索引文件或第二份持久化真相。

参考边界：Reasonix 使用 BM25 做保守词法召回；Hermes 已用 FTS5 trigram 处理 CJK。知己复用其“词法优先、来源可追踪”的原则，但当前数据量和 Markdown 权威仓储不值得新增 SQLite 生命周期。

### 2.3 不采用方案

- 不自写 BM25/TF-IDF 排序器；
- 不维护大规模手工同义词表；
- 不引入 embedding、向量数据库、混合检索、外部记忆 SaaS 或 MCP Server；
- 不把模型候选词当成用户事实、记忆或引用来源；
- 不缓存持久化索引，避免更新、删除、备份和迁移产生第二真相。

## 3. 工具契约

工具名：`zhiji.memory.search`

输入：

```json
{
  "query": "原始查询，1-200 字符",
  "alternates": ["可选候选查询，最多 3 项，每项 1-80 字符"],
  "limit": "可选整数，1-8，默认 8"
}
```

兼容要求：

- `query` 保持必填，既有调用无需修改；
- `alternates` 可选，未知字段继续由共享 Zod Schema 拒绝；
- Agent 只在自然问题与记录可能存在词汇差异时生成候选查询，不得填入结论、日期或不存在的事实；
- 候选项 trim、去重并受长度/数量限制；无合法候选时只搜索原始查询。

输出保持不变：

```json
{
  "kind": "memory.search",
  "hits": [
    {
      "id": "journal_xxx | review_xxx | pattern_xxx",
      "kind": "journal | review | pattern",
      "date": "YYYY-MM-DD 或 null",
      "excerpt": "有限脱敏原文摘录"
    }
  ]
}
```

`limit` 只控制结果数，不扩大摘录长度或读取范围。输出仍经过共享 Zod Schema 和 Main Process `safeText`。

## 4. 数据源与索引生命周期

| 来源 | 索引字段 | 输出日期 |
|---|---|---|
| 日志 | `body`、日期、项目关联 ID | 日志日期 |
| 复盘 | `body`、类型、周期、项目 ID | 周期结束日 |
| 已确认验证模式 | `statement`、`evidenceSummary`、来源复盘 ID | 创建日期 |

所有读取复用现有 repository/service 的 `list()`，不直接拼接文件路径，不绕过 Schema。索引只存在于一次 `search()` 调用内；搜索完成后由垃圾回收释放，不进入备份和数据迁移。

## 5. 中文 tokenizer 与查询处理

1. 对文档和查询使用相同的 Unicode 归一、大小写归一和 tokenizer。
2. `Intl.Segmenter` 提供 word-like 词项；移除空白和纯标点。
3. 同时为连续 CJK 片段生成二元词片；去重后交给 MiniSearch。
4. 常见虚词过滤必须小而可解释；不得引入覆盖业务词的大停用词表。
5. 英文和数字保留标准词项；中文不启用通用 Levenshtein fuzzy，避免单字近似导致误召回。
6. 原始完整短语命中获得额外加权，但不能绕过 BM25+ 的词项相关性。
7. 原始查询和 `alternates` 分别搜索，按记录 ID 合并；同一记录取最高相关性，并记录实际命中词用于摘录定位。
8. 分数相同时按日期从新到旧，再按稳定 ID 排序。

## 6. 摘录

- 摘录从 MiniSearch 返回的实际命中词附近截取，最多 800 字符；
- 若只有候选查询命中，仍必须从原始权威正文截取，不展示候选词为“原文”；
- 标准化字符串位置不能直接当作原文索引；实现应在原文中重新定位命中词，避免空白归一造成偏移；
- Dispatcher 再执行既有 `safeText`，路径或 URL 内容继续省略。

## 7. 安全与生命周期

- 工具只读，不允许写入、修改或删除记忆；
- Utility Process 不获得任意文件读取，Renderer 不获得索引或仓储对象；
- 不返回绝对路径、原始 URL、凭证或无限长度正文；
- 搜索失败沿用现有中文工具错误；空结果是正常结果，不伪造“记得”；
- 不删除或放宽任何既有确认、认证、数据目录、备份、IPC 和错误脱敏措施；
- 新依赖在实施前检查许可证、维护状态、包内容和传递依赖，并由现有 lockfile 固定解析结果；不新增独立供应链 gate。

## 8. 验收场景

普通测试必须覆盖：

1. **直接关键词**：“行动”仍命中日志、复盘和验证模式；
2. **中文复合查询**：“我以前是不是经常把行动定得太大”能够命中包含“行动拆成更小步骤”的日志；
3. **有限同义候选**：原始查询“任务总定得太大”配合候选“行动 拆解 步骤”命中同一日志；不提供候选时不伪造语义命中；
4. **噪声控制**：只有“以前、是不是、经常”等泛词时不返回大量无关记录；
5. **排序**：相关性优先，分数相同再按日期和 ID 稳定排序；
6. **摘录**：来自真实正文命中位置，长度受限，路径/URL 不跨工具桥；
7. **契约**：`alternates` 超数量、超长度、空值和未知字段被拒绝；
8. **兼容**：只传 `query` / `limit` 的既有工具调用保持通过。

这些是针对已确认失败的普通测试，不建立独立 baseline、hash 或质量 gate。

## 9. 后续升级条件

只有普通实现仍出现可复现失败时才继续：

1. 当前内存 BM25+ 无法处理实际数据量或更新成本，再评估可重建的 SQLite FTS5 trigram；
2. 受限候选查询仍无法处理隐含语义，且有明确演示/业务场景，再评估本地 embedding 或可替换 Provider；
3. 任何升级都必须保留来源 ID、时间、作用域、用户删除路径和 Markdown 权威真相。
