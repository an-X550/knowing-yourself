# 需求目标

收紧月度视角处理中间产物，让 `monthly-processor` 和生活类视角输出“证据包/综合材料”，而不是提前写成小报告。

> 作为月度综合引擎，我想拿到可交叉验证的证据、模式候选和边界说明，而不是各视角已经写好的半成品报告，以便最终月报能按主题综合而不是按视角拼接。

# 边界约束

- 不做什么：本阶段不删除视角、不改命令入口、不改输出路径、不改最终月报章节骨架、不重复第 1 阶段的 `monthly-synthesis` 主题归并改造。
- 影响范围：优先修改 `.claude/agents/monthly-processor.md`、`perspectives/therapist.md`、`perspectives/values-meaning.md`；视情况轻量推广到其他 `perspectives/*.md` 的角色与输出约束。
- 技术约束：保持 Markdown + YAML frontmatter；保持简体中文输出；保留证据日期要求；不引入新依赖或新工作流。

# 验收标准

- [ ] `monthly-processor` 明确把中间产物定义为“证据包/综合材料”，禁止写最终总结、结论章节和下月建议。
- [ ] `therapist` 和 `values-meaning` 的输出格式从长叙事收紧为“关键发现候选 + 证据表 + 反例/证据不足 + 交给综合引擎的材料”，减少最终月报式表达。
- [ ] 其他生活类视角中明显的小报告倾向被轻量收紧；方法论视角保留评分/诊断职责，不提前删除或合并。
- [ ] 输出验证能确认目标文件不再使用“创建报告/读回报告”等中间产物表述，并保留证据日期约束。

# 实施计划

1. 修改 `.claude/agents/monthly-processor.md`：重命名职责为月度证据包处理器，新增中间产物边界、证据包通用结构和禁止抢活规则。
2. 修改 `perspectives/therapist.md`：把心理视角从叙事分析改为心理证据包，保留风险/保护因素但要求短句、证据日期、反例和证据不足。
3. 修改 `perspectives/values-meaning.md`：把意义视角从哲学小报告改为意义证据包，保留价值对齐数据但压缩叙事、删除意义商数的最终判断倾向。
4. 审视其他 `perspectives/*.md`：只对明显抢综合职责的表述做轻量约束，不提前删除视角。
5. 运行文本扫描和 diff 验证，确认第 2 阶段边界满足后再进入第 3 阶段视角审计。
