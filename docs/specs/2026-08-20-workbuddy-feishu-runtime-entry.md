# WorkBuddy 多通道运行入口：统一路由与受限写入

## 问题与目标

飞书智能体已能通过 WorkBuddy 访问本地“知己”项目，但现有消息没有稳定路由到项目的运行入口：它曾自行生成偏离日反馈契约的模板、只返回分析却未保存日志和反馈。根因是把只读分析器 `daily-analyzer` 当成了完整入口；实际持久化由 `log` skill 编排。该问题属于 WorkBuddy 的消息适配层，不属于飞书本身，因此同一规则也应适用于微信等上游通道。

目标是在不复制任何日/周/月分析模板的前提下，建立一个唯一的 WorkBuddy 消息适配层。该层将消息映射到既有 `.claude/` 权威定义，限制每个意图的读取、写入和确认边界，并让原消息通道只回复已经被本地复读验证的结果。

## 第一性原理与范围

原始日志是高频、可追加的证据；日反馈是短周期的实验记录；`verified-patterns.md` 是有阈值的验证沉淀；核心画像、当前状态和主题认识是慢变量。不同证据寿命与误写代价要求不同写入权限，不能由单次飞书消息自动升级。

本次创建 WorkBuddy 多通道运行入口、其可复制固定提示词和回归测试。它不修改既有分析模板、报告结构、模型、外部分发逻辑或开发类命令；不把 git、配置、部署、提交、代码开发能力暴露给任何消息通道。

## 架构

```text
WorkBuddy 任意消息通道
  -> 固定系统提示词（只进入本地项目并读取入口契约）
  -> .claude/workflows/workbuddy-feishu-entry.md
  -> 意图路由到既有 log / review / topic-thinking 等定义
  -> 默认仅本地持久化、复读校验
  -> 用户本次明确要求时，按既有分发契约执行可选外部副作用
  -> 原消息通道返回已验证结果或一条澄清问题
```

入口契约是唯一新增的运行真相；固定提示词只引用它，不重复路径、模板和业务规则。

## 路由与权限

| WorkBuddy 消息 | 权威运行定义 | 允许写入 | 禁止写入 |
|---|---|---|---|
| 未命中下列显式意图的单条日志 | `log.md` + 其引用契约 | 日志原文、当日反馈、满足验证契约的 `verified-patterns.md`、既有投递闭环必需的 `readiness_delivery_state` | 其他 `关于我`、周期报告、主题文件 |
| `周复盘` | 自然语言复盘路由中的周报定义 | `output.weekly_report` | 其他长期上下文 |
| `月复盘` | 自然语言复盘路由中的月报定义 | `output.monthly_report` | 其他长期上下文 |
| `项目复盘：<主题>` | 自然语言复盘路由中的项目定义 | `output.project_report` | 其他长期上下文 |
| `主题思考：<问题>` | `topic-thinking.md` | 无 | 所有主题文件及其他项目文件 |
| `确认沉淀：<主题>` | `topic-thinking-persistence.md` | 仅被确认主题与索引 | 无关主题、核心画像、周期报告 |
| `现在该补什么？` 等复盘时机问题 | `review.md` + `review-readiness-checker.md` | 无 | 所有项目文件 |
| 明确的年度复盘 / 人生设计 / 日志质量检查 | 对应现有 command 与 agent | 仅 `paths.md` 声明的对应报告 | 其他上下文文件 |

日记默认路由只适用于这个专用飞书智能体。消息若不能满足既有 `log.md` 的日期与证据要求，入口只能追问一个会改变存档对象的问题，不能保存或分析。

所有成功写入必须按既有定义复读并通过最低结构校验；失败时只报告失败，禁止声称已保存。默认仅本地，避免把消息入口误当作外部分发授权；但用户本次明确要求同步刚生成的允许结果时，在本地成功后委托既有结果分发契约决定是否、如何分发。它的来源白名单、配置开关、幂等、渠道权限与确认门不由本入口重复定义。

## 长期上下文保护

`context.core_profile` 与 `context.current` 永远不在飞书运行入口的直接写入白名单中。周/月/项目复盘只可在聊天结果末尾列出“拟议长期变更：结论、证据、目标文件”；未收到用户在飞书中的明确确认前不得写入。

主题思考严格采用既有两阶段规则：首次讨论只读；确认沉淀时才读取持久化契约并写入。若 WorkBuddy 不能访问足以支撑确认的同一会话上下文，必须要求用户提供要确认的摘要，不能猜测或写入。

1. 新增 `.claude/workflows/workbuddy-feishu-entry.md`，提供路由、读取顺序、白名单、禁止事项、回复与失败语义。
2. 新增 `docs/workbuddy-feishu-agent-prompt.md`，提供飞书智能体可直接粘贴的固定提示词及最小配置步骤。
3. 新增 `tests/workbuddy-feishu-entry-contract.tests.ps1`，静态验证：入口和提示词存在、路由引用存在、没有复制日反馈模板、每日与长期写入边界、主题确认门、仅本地规则。
4. 更新项目入口事实、版本、状态和变更记录。

自动测试不能模拟 WorkBuddy 或飞书平台，另保留一次人工验收：发送一份脱敏单日日志，确认原文与反馈均落到权威路径、反馈符合日契约、`verified-patterns.md` 只按验证规则变化；再分别验证周复盘、主题首次讨论和确认沉淀的写入边界。
