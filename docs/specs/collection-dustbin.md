# 需求目标

新增“收藏吃灰库”自然语言收录能力：用户明确要求收录一篇外部内容并指定主题时，AI 将内容提炼并保存为可检索的 Markdown，方便以后按问题查找原文。

> 作为长期收集有用信息的用户，我想把文章、摘录和链接统一存到 `关于我/收藏吃灰库/`，以便在遇到具体问题时由 AI 找回相关原文，而不是重新搜索或翻多个软件。

# 边界约束

- 不做什么：不新增 Slash Command；不要求用户手动填写模板；不建立答案卡、评分、定期复习或独立数据库；不自动收录普通聊天内容。
- 触发条件：用户在同一请求中明确表达“收录”，并提供主题目录与可提炼内容。自然语言表达即可，例如“把这篇收录到收藏吃灰库的健身目录”。
- 存储位置：`关于我/收藏吃灰库/{主题}/{文章标题}.md`。主题由用户指定；不存在时创建。路径名须过滤不安全字符并确认仍位于收藏吃灰库内。
- 固定正文格式：每篇文件只包含 `# 标题`、`## 摘要`、`## 关键词`、`## 原文 / 摘录全文`、`## 原文链接` 五个部分。
- 内容边界：有正文或可读摘录时才生成摘要和关键词；只有链接且当前无法读取时，要求用户提供正文或摘录，不能编造。原文链接缺失时明确写“未提供”。
- 重复处理：发现同一原文链接或同主题目录下近似标题时，先询问用户更新已有文件还是新建文件。
- 查询边界：用户明确要求查询收藏吃灰库时，递归搜索标题、摘要、关键词和原文；返回最相关条目及其本地路径和原文链接。普通聊天不自动全量读取资料库。
- 影响范围：新增收录路由与共享路径约定，补充检索行为和静态测试；`关于我/` 个人内容继续保持 gitignore，不进入发布包。

# 验收标准

- [ ] 用户用自然语言指定“收录”、主题和文章内容后，AI 在对应主题目录创建符合固定五段式格式的 Markdown。
- [ ] 用户只给出不可读链接时，AI 明确索要正文或摘录，不生成臆测摘要。
- [ ] AI 可针对明确的查询请求，从多个主题目录中按标题、摘要、关键词和正文找回相关条目，并提供本地文件路径和原文链接。
- [ ] 重复链接或近似标题不会静默覆盖现有内容。
- [ ] 路径越界、无主题、无内容等异常都有明确的澄清或降级行为。

# 实施计划

1. 在共享路径契约中定义收藏吃灰库根目录和主题文件路径，并新增自然语言收录 skill，落实触发、提炼、写入、重复检查和异常处理。
2. 增加明确查询时的资料库检索规则，使其只在用户主动查询时读取相关文件并返回来源。
3. 为收录、链接内容不足、重复、路径安全与查询命中编写静态回归测试；同步用户版运行镜像与分发边界（如适用）。
4. 更新运行入口说明、项目状态与发布记录，并执行相关测试。
