# 桌面端开发路线图与连续执行任务书（2026-08-14）

> 目标：把 `apps/zhiji-desktop/` 开发为与 Skill 系统**契约行为同构**的完整产品。
>
> 原则：同构的标准是"契约行为一致"（结构、判据、质量门、版本纪律），不是代码级 1:1 复刻；全程第一性原理与高性价比——每个阶段只解决证据支持的问题，能复用就不新造，能登记就不开发。
>
> 本文件是连续执行任务书：阶段 A → B → C 依次执行，阶段 D 证据触发才启动。

## 1. 当前能力盘点（2026-08-14 核实）

桌面端已具备：日反馈（`daily-review-v3`）、周期复盘周/月/项目（`periodic-review-v3`，已与 Skill 同构）、日志质量教练（`journal-coach-v2`）、年度回顾（`yearly-review-v1`，要求 ≥6 份月报）、方向校准（`life-design-v1`）、验证模式沉淀、主题思考与受控联网、模糊意图路由。

**真实缺口（按证据强度排序）**：

| # | 缺口 | 证据 | 伤害 |
|---|---|---|---|
| 1 | 证据分级正则与语义判据分歧 3/5，含 D 级误熔断 | `docs/2026-08-14-r2-evidence-grading-comparison.md` | 用户得不到反馈，核心闭环被打断 |
| 2 | 月报深度未实现（主主题归并 + life-design 升级提醒） | 兼容快照 deferred 项 | 月报质量低于 Skill；延后理由（桌面无 life-design）已随 `life-design-v1` 落地而消除 |
| 3 | yearly / life-design / coach 三条链路未经契约同构审计 | 上轮审计只覆盖 daily + periodic | 可能存在与 R3/R6 同类的结构漂移，目前无证据、无对照表条目 |
| 4 | 产品工程完整度：关闭窗口草稿保护、旧格式迁移器、目录迁移、合并恢复、独立假说台账 | `PROJECT_STATUS.md` Windows 桌面客户端行 | 使用摩擦与数据安全风险，无真实事故证据 |

## 4. 阶段 B：月报深度补齐

### 4.1 闸门证据（开工报告须复核）

- 契约依据：`.claude/shared/contracts/review-synthesis.md` 「月报深度」四条（只读）。
- 现状：`periodic-review-v3` 对 weekly/monthly/project 使用同一 schema，月报无主主题归并、无升级提醒；兼容快照 deferred 明确登记该缺口。
- 延后前提已消除：桌面端已有 `life-design-v1` 方向校准入口（`reviews-page.tsx` 可选类型）。

### 4.2 精确改动对象（预估，开工时以代码核对为准）

- `src/main-process/prompts/periodic-review-v1.ts`：版本常量 `periodic-review-v3` → `v4`；schema 增加月报专用字段（`mainThemes`：主题名 + 支持视角 + 关键证据 + 反例或证据不足 + 对重来/下月规划的意义，2-3 条；`escalationReminder`：可选字符串）；提示词补月报深度四条；`renderPeriodicReview` 月报分支渲染主主题节与升级提醒；`applyPeriodicQualityGates` 不变或按需扩展。
- `src/main-process/skill-runtime/periodic-runtime.ts`：月报材料组装保持"下游沉淀优先"（周复盘为主材料），不新增读取面。
- 兼容快照 `desktop-periodic-review-v2` → `v3`；兼容矩阵月报深度行由"延后"改为"本阶段实现"；契约对照表增补条目与漂移防护断言。
- 测试：`periodic-review-v1.test.ts`、`periodic-runtime.test.ts`、`generate-periodic-review.test.ts`。

### 4.3 工作项（TDD）

1. **红测**：月报输出含 2-3 个主主题（五要素齐全）、下月规划含"目标 + 手段 + 检查点 + 假说"、触发条件满足时出现升级提醒、周报/项目复盘不受影响（回归）。
2. **实现**：schema、提示词、渲染、快照递增。升级提醒措辞按桌面语境改写：指向"复盘页的方向校准（life-design）"，不出现 `/life-design --quick` 命令字样，不自动生成 life-design 报告。触发条件照搬契约四条（长期方向冲突、重复卡点、工作观/人生观冲突、下月规划只能局部修补），基于证据、至多一条。
3. **验证与治理**：同贯穿纪律；CHANGELOG 记录月报深度落地。

### 4.4 检查点（全部满足才进入阶段 C）

- [ ] 月报测试全过；周报与项目复盘渲染零变化（回归断言）。
- [ ] 主主题为空或仅 1 条时，按证据不足披露而非硬凑（契约"不强行制造"）。
- [ ] 全量 `npm test` / typecheck / lint 通过。
- [ ] 本阶段独立提交；治理文件同步。

## 5. 阶段 C：yearly / life-design / coach 契约同构审计

### 5.1 方法（审计优先，复用 R1/R3/R6 方法论）

只读对照 `.claude/` 对应命令与契约 vs 桌面提示词、schema、渲染与材料规则，逐链路产出结论：**同构 / 漂移（列差异）/ 设计性差异（登记不修）**。无实质漂移则只登记，不写代码。

### 5.2 审计清单（已知疑点，执行时逐条取证）

| 链路 | 桌面现状 | 对照对象 | 已知疑点 |
|---|---|---|---|
| yearly | `yearly-review-v1`，自由 Markdown，≥6 份月报（`insight-materials.ts`） | `.claude/commands/yearly-review.md`（12 份月报生成年度综合） | 月报数量门槛 6 vs 12 是否设计性差异；输出结构是否需要稳定六问或既有结构 |
| life-design | `life-design-v1` 快速模式（问题重述/张力与资源/两方向/7 天实验/可观察判据） | `.claude/commands/life-design.md`（可验证的未来原型实验） | 原型实验可验证性约束、材料范围（长期日志+日反馈+复盘）是否对齐 |
| coach | `journal-coach-v2` 独立结构化契约 | `.claude/commands/journal-coach.md` 及对应 agent | 六步法判据、A-D 就绪度定义是否与 `journal-input.md` 一致 |

### 5.3 工作项

1. **产出审计报告**：`docs/2026-08-14-insight-contract-audit.md`，每链路给结论、证据行号级引用、差异分级（结构漂移 / 判据漂移 / 设计性差异）。完成后向我报告结论。
2. **条件修复**：仅结构漂移与判据漂移立项修复（TDD、版本常量递增、快照与对照表同步）；设计性差异只登记进兼容矩阵与对照表。
3. **验证与治理**：同贯穿纪律。

### 5.4 检查点（全部满足才收尾）

- [ ] 三链路审计结论均有行号级证据，无"推测性差异"。
- [ ] 所有修复走 TDD 且有回归测试；所有不修项有登记。
- [ ] 全量验证通过；治理同步；完成报告按第 7 节格式。

## 7. 贯穿纪律（每阶段通用）

- 代码只改 `apps/zhiji-desktop/`；`.claude/` 只读，是唯一 Skill 运行真相。
- TDD 先红后绿；语义或行为变化必须递增版本常量并同步兼容快照、兼容矩阵、契约对照表。
- 每阶段完成跑 `npm test` / `npm run typecheck` / `npm run lint`（0 error，warning ≤ 基线 5），涉打包链变化补跑 `npm run package`。
- 治理同步：VERSION 每阶段递增一次、CHANGELOG 顶部追加发布级记录、PROJECT_STATUS 同步待办与决策。
- 每阶段一个聚焦提交（或按工作项拆分），本地提交可执行，推送由用户手动。
- 最终完成报告（阶段 C 收尾时给出）：各阶段改动文件、用户可见行为变化、未完成项与登记项、精确验证命令与结果、全部提交哈希。
- 不做：飞书/滴答分发复刻（桌面本地优先边界）、向量库、跨设备同步、清单外入口、安装/部署类人工验收事项。
