# 知己

> 一个以 Agent 为执行入口的中文个人日志闭环：从真实记录中找证据，形成一个小行动，再用下一次记录验证。

## 先看它解决的真实问题

人能记住当天的感受，却很难从多天、多周的记录中看见重复模式；看见一个模式后，又常常没有低成本的验证方式。知己不以生成更多报告为目标，而是把这条闭环做短：

```text
真实记录 → Agent 检索证据 → 一个可执行的小行动 → 记录结果 → 校准认识
```

判断一个能力是否属于知己，标准不是“其他 Agent 有什么”，而是它是否直接改善“发现模式 → 形成行动 → 后续验证”。不能改善这条闭环的能力，不会因为听起来先进就成为默认功能。

## 知己 Agent：把材料变成下一步

知己 Agent 不是日记代写器，也不是可以操作整台电脑的通用代理。它是在受控工具边界内，帮助你完成四件事：

1. **找证据**：从日志、日反馈、周/月/项目复盘、项目和已确认验证模式中检索相关内容。
2. **做有限推理**：在一次会话中按需读取多份材料，区分事实、推断和待验证假说；必要时搜索公开来源，并保留来源标识、标题、域名、摘要和时间。
3. **给出行动**：把结论收敛为一个明天或下一次记录中可以检查的小实验，而不是堆出一串建议。
4. **守住确认门**：涉及正式日志、反馈或复盘的改变，先展示预览，再由你确认；会话可以保存、恢复和重放，但不会绕过确认替你做重大决定。

Agent 当前能做什么，和不能做什么，必须分开看：

| 能做 | 不会默认做 |
| --- | --- |
| 受限读取本地日志、复盘、项目和验证模式 | 任意读取文件、执行 Shell 或控制桌面 |
| 受控搜索公开来源并按来源回读 | 接收或展示任意网页 URL 作为可执行指令 |
| 在工具结果驱动下完成有限多步会话 | 后台常驻、定时自行运行或启动子 Agent |
| 通过结构化工具完成预览—确认—执行流程 | 证据不足时编造事实，或自行修改代码、Skill 和权限 |

技术细节与能力边界见 [Agent 能力第一性原理分析](docs/2026-08-22-agent-capabilities-first-principles-analysis.md)；当前状态与未验证事项见 [PROJECT_STATUS.md](PROJECT_STATUS.md)。

## 最小可用闭环

在 Windows 桌面客户端的 Agent 页面，或能读取项目目录的 Codex / Claude 中，直接给出一段真实日志，再说：

```text
请先检索我最近的日志和已确认的验证模式，找出一个我可能没看到的重复模式。
区分事实与推断，只给一个明天可验证的小实验，并告诉我下次要记录什么结果。

日志：今天本来要完成方案，但我一直整理资料，直到晚上也没开始写正文。
```

下一次记录时只需补上：

```text
上次实验：做了 / 没做 / 做了一部分
结果：发生了什么
判断：支持原假说 / 出现反例 / 仍待验证
```

这就是知己的最小闭环。先让一次行动得到验证，再考虑更长周期的复盘；没有行动和验证时，增加报告通常不会带来更多改变。

## 选择适合你的入口

| 入口 | 适合谁 | Agent / 工作方式 |
| --- | --- | --- |
| [Windows 桌面客户端](apps/zhiji-desktop/README.md) | 不想使用 CLI、希望本地可视化操作的人 | 六个入口：开始、Agent、日志、复盘、项目、设置；Agent 负责会话、证据检索、受控联网和有限工具回合，数据保存在本地 Markdown/JSON |
| Codex 或 Claude | 能让 AI 读取项目目录、并希望直接使用 Skill/命令的人 | 直接用自然语言；Claude 保留 Slash Command 兼容入口，`.claude/` 仍是 Skill、命令和工作流的运行真相 |
| [知己 DSH 独立插件](apps/zhiji-dsh-plugin/README.md) | 已安装 DeepSeek Harness、希望在 DSH Web UI 中工作的人 | 粘贴单日、周、月或项目材料；配置 `ZHIJI_DSH_LOG_ROOT` 后可按日期范围只读聚合 Markdown，不读取桌面端或直接写正式报告 |
| WorkBuddy 远程助理 | 需要手机消息入口的人 | 通过一次配置的项目绝对路径路由 `[知己]` 消息；可做日志、复盘和主题讨论，外部写入仍需保留人工授权 |

## 可以直接对 Agent 说什么

| 目标 | 示例请求 | 结果 |
| --- | --- | --- |
| 找出重复模式 | `先检索我的日志，找出最近反复出现但我可能没注意到的模式` | 带依据的模式、事实与推断的区分、一个验证动作 |
| 完成今日反馈 | `根据今天的日志做反馈，只给一个盲点和一个五分钟行动` | 昨日闭环、一个有证据的盲点、一个可观察预测 |
| 做历史检索 | `找出我最近三次在项目推进上卡住的共同点，并列出原文依据` | 当前回合可核实的只读证据，不复制出第二份记忆 |
| 做周期复盘 | `对上周做复盘，先告诉我需要哪些材料，确认后再生成` | 周/月/项目复盘预览、趋势、反例和下一步 |
| 查公开资料 | `先查公开资料解释这个概念，再说明它和我的记录有什么关系` | 受控来源搜索与来源绑定的读取；不把网页内容伪装成本地事实 |
| 重新校准方向 | `我想重新检查最近的生活方向，先指出冲突和证据缺口` | 方向校准与可验证的小实验，不替你做价值选择 |

日反馈优先于周、月和年度回顾：材料不足时，Agent 应建议先完成最近一次小闭环，而不是制造一份看似完整的报告。

## 隐私与结果边界

- 本地 Markdown/JSON 是权威记录。真实日志默认不进入 Git；这不等于加密或访问控制，请只提供你愿意交给当前 AI 服务处理的内容。
- Windows 桌面端的 API Key 只在 Electron Main Process 使用，并通过 Windows `safeStorage` 保存；Renderer 不直接接触密钥、任意网络或文件系统。
- Agent 的本地检索保持只读并带来源边界；公开联网是受控工具能力，不会因此获得任意浏览器、Shell 或电脑控制权限。
- AI 负责整理证据、提出假说和设计低成本实验；你保留对经历、价值选择和重大决定的最终解释权。证据不足时，应降低结论强度，而不是补完故事。
- 日志、反馈与复盘的正式写入沿用预览—确认—执行边界；可选的飞书沉淀与滴答行动分发默认关闭，本次只想保存在电脑时，直接说“仅本地”。

完整的隐私、目录与可选分发设置，请见 [用户版使用指南](zhiji-user/README.md) 和 [结果分发设置](docs/result-distribution-setup.md)。

## 手机记录入口

本地飞书日反馈入口已于 2026-08-20 **弃案**，当前不应部署。日常消息交互推荐 WorkBuddy 远程助理：它固定运行在专属文件夹，因此必须通过一次配置的项目绝对路径进入知己工作空间；用户版现随包提供[WorkBuddy + 飞书智能体部署说明](zhiji-user/docs/workbuddy-deployment.md)，包含人工配置、自定义提示词、飞书云文档、滴答 MCP 与 AI 一键部署步骤。日常消息以 `[知己]` 开头即可路由日志、周/月/项目复盘与主题思考，无需重复路径；`仅本地` 可同时跳过飞书和滴答。详见[弃案说明](docs/local-feishu-daily-feedback-entry.md)。
